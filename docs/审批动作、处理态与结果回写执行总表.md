## 4. 审批状态机总表

| 状态 | 含义 | 前端表现 | 可流转 |
|---|---|---|---|
| `pending` | 待用户决策 | 显示确认/驳回按钮 | `processing/expired` |
| `processing` | 决策命令已发出，等待 ack/回写 | 按钮禁用，显示处理中 | `approved/rejected/failed/expired` |
| `approved` | 已确认 | 显示确认人、时间、备注 | 终态 |
| `rejected` | 已驳回 | 显示驳回人、时间、备注 | 终态 |
| `failed` | 决策提交失败或回写失败 | 展示重试按钮 | `processing/expired` |
| `expired` | 审批已超时失效 | 按钮禁用，提示重新触发 | 终态或进入新审批 |

## 5. 审批动作矩阵

| 动作 | 当前状态 | 正式行为 | 结果写回 |
|---|---|---|---|
| 确认审批 | SDK 能力已备，UI 未接 | 卡片内直接确认 | 审批卡片 + 对话流 + 列表标签 |
| 驳回审批 | SDK 能力已备，UI 未接 | 卡片内直接驳回 | 审批卡片 + 对话流 + 实例终止态 |
| 解释后再决策 | 当前靠草稿 | 保留，作为次级动作 | 新消息进入对话流 |
| 再次提交 | 当前无处理态 | 失败态支持重试 | 失败记录替换为 processing |
| 查看审批上下文 | 当前无 | 展开理由、成本、风险、目标文件 | 不改变审批状态 |

## 6. 正式执行链总表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | `approvalId + decision + note?` | 发起 HTTP 或 realtime 审批 | `approval_resolution_command` |
| 2 | 前端 | 提交中 | 卡片转 `processing` | 防抖与防重复 |
| 3 | API | 审批命令 | 严格按 `approvalId` 查找待审批对象 | 更新审批状态 |
| 4 | API | 决策结果 | 更新 run 状态与系统消息 | 新快照 |
| 5 | Realtime/Event bus | `run.status.changed`、`conversation.message`、`approval.resolved` | 广播 | 前端收敛显示 |
| 6 | 前端 | 收到回写 | 卡片改为 `approved/rejected`，更新列表和计数 | UI 闭环 |

## 7. HTTP / Realtime 协同矩阵

| 场景 | 优先通道 | 回退通道 | 判定规则 |
|---|---|---|---|
| WebSocket 已连通 | realtime `approve()` | HTTP `approveRun()` | 优先保持低延迟 |
| WebSocket 不可用 | HTTP | 无 | 进入同步提交 |
| realtime 已发但未收到 ack | realtime 等待超时 | 回退 HTTP 或标 `failed` | 防止重复审批 |
| 页面恢复后发现仍 pending | 重新拉取快照 | 无 | 以服务端状态为准 |

## 8. 结果回写目标矩阵

| 回写目标 | 当前状态 | 正式要求 |
|---|---|---|
| 对话消息流 | 已有系统消息 | 增加审批标题、决策人、备注摘要 |

| 审计域 | 当前无正式落点 | 记录决策人、渠道、来源 IP/端、备注 |

## 9. 前端处理态矩阵

| 状态 | 卡片主按钮 | 次按钮 | 页面其他联动 |
|---|---|---|---|
| `pending` | 可点击确认 | 可点击驳回/解释 | 顶部显示待处理数 |
| `processing` | 禁用 + loading | 禁用 | 阻止重复操作 |
| `approved` | 转为已确认标签 | 可查看详情 | 列表计数减少 |
| `rejected` | 转为已驳回标签 | 可查看原因 | run 可能进入 `CANCELLED` |
| `failed` | 显示重试 | 可改走解释链 | 提示错误码 |
| `expired` | 禁用 | 提示重新拉起流程 | 列表从待审批移出 |

## 10. 结果消息模板矩阵

| 场景 | 建议消息类型 | 建议内容 |
|---|---|---|
| 审批通过 | `system/approval` | 说明哪个审批已通过、由谁通过、执行继续 |
| 审批驳回 | `system/approval` | 说明哪个审批被驳回、执行终止或回退 |
| 审批失败 | `system/error` 或 `approval.failed` | 提示提交失败、可重试 |
| 审批超时 | `system/status` | 说明审批窗口已失效，需要重新发起 |

## 11. 多审批并发矩阵

| 场景 | 当前风险 | 正式要求 |
|---|---|---|
| 同一 run 有多个 pending approval | service 会命中首个 pending approval | 必须严格按 `approvalId` 更新 |
| 用户重复点击确认 | 可能重复提交 | 前端 processing 防重，后端幂等 |
| 一端处理后另一端未刷新 | 状态可能过旧 | snapshot/event 双通道收敛 |
| 审批跨端处理 | H5 与 Dashboard 都可能操作 | 服务端权威，前端只消费回写 |

## 12. 错误与恢复矩阵

| 场景 | 当前状态 | 正式行为 |
|---|---|---|
| `approvalId` 不存在 | 当前可能误处理首个 pending | 返回结构化错误，卡片转 `failed` |
| 已处理审批再次提交 | 当前语义不清 | 返回幂等已处理结果 |
| run 已结束仍提交审批 | 当前可能冲突 | 返回 `RUN_STATUS_INVALID` |
| realtime 断线 | 当前无专用提示 | 卡片留在 `processing`，超时后转 `failed` |
| API 成功但回写延迟 | 当前无处理中态 | 用本地临时 `processing` 直到 snapshot 更新 |

## 15. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| `approvalId` 未被严格消费 | 多审批场景存在误决策风险 | 业务正确性受损 | P0 |
| 双端无 direct approve/reject | 用户要靠补草稿 | 审批链效率低 | P0 |
| 无 processing/failed 状态 | 用户无法判断是否已提交 | 易重复操作 | P0 |
| Dashboard 无审批卡片层 | 重度用户缺主操作台 | 产品定位不完整 | P1 |
| 通知与审计未联动 | 审批闭环不完整 | 治理与追责弱 | P1 |
