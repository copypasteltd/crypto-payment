## 2. 文件链当前事实矩阵

| 能力 | 当前实现 | 当前结论 | 当前缺口 |
|---|---|---|---|
| 文件读取边界 | `resolvePathWithinTarget()` | 已限制请求不能越出 `targetPath` | 无用户/工作区级授权 |
| 文件树扫描 | API `walkDirectory()`、Bridge `walk()` | API 与 Bridge 都可扫描目录 | 存在逻辑重复 |
| 文本预览 | `readRunFile()` 最多 256 KB | 已有基础文本预览 | 无图片/PDF 正式预览分流 |
| 下载 | `createDownloadDescriptor()` | 可直接流式下载 | 无下载授权 session |
| 文件同步 | `FileWatcher.sync()` -> `files.synced` | target path 可回流到 API/前端 | 无去抖批处理策略 |
| 单文件变更 | `emitFileChanged()` -> `file.changed` | 可推单文件变化 | 高频变更可能放大事件量 |
| 产物发布 | `ArtifactPublisher.flush()` -> `artifact.ready` | outputs 中新文件可标记为 artifact | 无对象存储归档与正式下载 URL |
| 本地持久化 | `runsRepository` + `runEventBus` | 当前可落本地 JSON/JSONL | 不适用于正式多实例 |

## 3. 路径边界解析执行矩阵

| 步骤 | 当前行为 | 代码位置 | 结果 |
|---|---|---|---|
| 根路径确定 | 从 `runsRepository.get(runId).run.targetPath` 取根 | `getRunRoot()` | run 级根目录 |
| 请求路径归一化 | 空值或 `/` 直接指向根，其余走 `path.resolve()` | `resolvePathWithinTarget()` | 得到 candidate |
| 相对路径校验 | `path.relative(rootPath, candidate)` | 同上 | 超出根目录则报 `FILE_PATH_INVALID` |
| stat 校验 | `fs.stat(absolutePath)` | `statRunFile()` | 不存在则 `FILE_NOT_FOUND` |

## 6. 文件树扫描执行矩阵

| 侧 | 当前函数 | 扫描范围 | 排序规则 |
|---|---|---|---|
| API | `walkDirectory(rootPath)` | 从 `targetPath` 递归扫描目录和文件 | 按 `path` 字典序 |
| Bridge | `walk(rootPath)` | 从 `targetPath` 递归扫描目录和文件 | 按 `path` 字典序 |
| Artifact | `listRunFilesUnderRoot(outputsPath)` | 从 outputs 递归扫描目录和文件 | 复用 Bridge `walk()` |

## 6.1 文件树回退执行矩阵

| 场景 | 当前行为 | 当前依据 |
|---|---|---|
| `targetPath` 可访问 | 动态扫描目录并刷新 `run_files` | `listRunFiles()` |
| `targetPath` 不可访问但 `run_files` 有记录 | 直接回退 `run_files` 索引 | `listRunFiles()` |

## 7. 文本预览执行矩阵

| 步骤 | 当前行为 | 输出 |
|---|---|---|
| 路径检查 | 先执行 `statRunFile()` | 确认路径未越界，并优先读 live file，缺失时回退索引 |
| 目录拦截 | 路径以 `/` 结尾则报错 | `FILE_PATH_INVALID` |
| 文件读取 | live file 走 `fs.readFile(...)`，缺失时走 `objectStore.createReadStream(...)` | 原始 Buffer / 对象流 |
| 截断 | 最大 `256 * 1024` 字节 | `truncated=true/false` |
| 响应 | `file + content + encoding=utf8 + truncated` | `RunFileReadResponse` |

## 9. `FileWatcher` 目录同步执行矩阵

| 阶段 | 当前行为 |
|---|---|
| 启动前目录创建 | 保证 `targetPath` 存在；如有 `outputsPath` 也创建 |
| 监听目标 | 监听 `targetPath`，如有 `outputsPath` 则一并监听 |
| 监听选项 | `ignoreInitial=true`，`awaitWriteFinish` 开启 |
| add/change/addDir | 若变化发生在 `targetPath` 下，则先发 `file.changed`，随后全量 `sync()` |
| unlink/unlinkDir | 直接全量 `sync()` |
| 初始启动 | `start()` 结尾先执行一次 `sync()` |

## 10. `files.synced` / `file.changed` 执行矩阵

| 事件 | 当前触发时机 | 当前载荷 |
|---|---|---|
| `file.changed` | `targetPath` 下新增/修改文件或目录 | 单个 `RunFileEntry` |
| `files.synced` | 启动时、任意变更后、删除后 | 当前完整 `RunFileEntry[]` |

## 11. `ArtifactPublisher` 执行矩阵

| 步骤 | 当前行为 | 结果 |
|---|---|---|
| outputs 目录保证存在 | `mkdir(outputsPath)` | 输出目录就绪 |
| 递归扫描 | `listRunFilesUnderRoot(outputsPath)` | 拿到所有候选文件 |
| 过滤目录 | 目录跳过 | 仅处理文件 |
| 指纹计算 | `path:size:mtimeMs` | 判定是否已发布 |
| 新产物生成 | `artifactId=art_<uuid>`，`status=ready` | `RunArtifact` |
| 发布事件 | emit `artifact.ready` | API 可回流产物 |

## 12. Repository 与 Event Bus 存档执行矩阵

| 组件 | 当前落盘格式 | 当前作用 |
|---|---|---|
| `runsRepository` | `runs/<runId>.json` | 保存 run 快照聚合体 |
| `runEventBus` | `events/<runId>.jsonl` | 保存事件历史与实时分发 |

## 13. 当前执行链全景矩阵

| 阶段 | 当前链路 |
|---|---|
| 容器/bridge 写文件 | Codex 或工具把结果写进 `targetPath` / `outputsPath` |
| Bridge 监听变更 | `FileWatcher` 捕获变更 |
| 发送事件 | 发 `file.changed` 与 `files.synced` |
| API 接收事件 | Bridge internal routes -> service -> repository/event bus |
| 前端收到更新 | WS/SSE -> SDK -> `applyBridgeEventToRunSnapshot()` -> query cache |
| 用户读取文件 | 前端调 `readRunFile()` / 下载 URL |
| 用户查看产物 | `ArtifactPublisher.flush()` 后前端通过 artifact/file 列表看到结果 |

## 14. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 文件扫描逻辑重复 | API 与 Bridge 各自维护 `walk + infer kind` | 维护成本高，存在漂移风险 | P1 |
| 只做路径边界，不做授权边界 | 当前只保证不越出 `targetPath` | 多用户场景文件安全不足 | P0 |
| 预览类型单一 | 文本预览统一 `utf8`，图片/PDF 无正式预览链 | 文件页体验不足 | P1 |
| 下载无授权票据 | 直接拼 URL 下载 | 链接难治理、难审计 | P0 |
| 产物无正式下载 URL | `downloadUrl = null` | 对外交付链不完整 | P0 |
| 事件粒度可能过密 | 高频变更会触发大量 `sync()` | 大目录场景性能风险 | P1 |

## 15. 正式收敛建议矩阵

| 方向 | 建议 |
|---|---|
| 文件元数据统一 | 抽出共享 `file-entry` / `file-kind` 工具，API 与 Bridge 共用 |
| 文件授权正式化 | 在路径边界之外增加 `workspace/run/user` 授权判定 |
| 预览能力分流 | 文本、图片、PDF、二进制下载分别走独立策略 |
| 下载会话化 | 引入 `download session` / 预签名链接 / 审计记录 |
| 产物对象存储化 | `artifact.ready` 之后同步到对象存储，生成正式 `downloadUrl` |
| 大目录优化 | `files.synced` 改为 watermark + diff，减少全量扫描频次 |
