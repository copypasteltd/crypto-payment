| 回调链观测与幂等不足 | register/status/events/artifacts 回调已闭环，但尚无 trace 贯通、幂等键与细粒度审计 | 影响复杂故障定位与重复投递治理 | P1 |
| 前端环境粒度过粗 | Dashboard/Mobile 仅有单一 API Base URL | 无法细分上传域名、下载域名、WS 域名 | P1 |
| 密钥未进入正式凭证系统 | 第三方 API Key 仍停留在设计层 | 无法正式治理第三方能力 | P0 |
| 配置变更无审计 | 当前无生效快照、无变更记录 | 故障定位与合规追溯困难 | P2 |

## 18. 建议优先收口的配置项表

| 顺位 | 收口项 | 具体动作 | 目标结果 |
|---|---|---|---|
| 1 | 集中 `config` schema | 为 API、worker、bridge、前端各建校验入口 | 启动即发现变量错误 |
| 2 | Bridge 回调可靠性 | 为 internal 回调补 trace id、幂等键、失败指标与更细重试策略 | 提升运行态可观测性与恢复性 |
| 3 | 前端多入口配置 | 拆分 API / WS / 下载等公开配置 | 支撑多域名与环境切换 |
| 4 | Secret Manager 接入位 | 将第三方 API Key 与 MCP 凭证转到正式密钥系统 | 满足脱敏、轮换、审计 |
| 5 | 分环境模板体系 | 为 dev/staging/prod 生成 overlay 与部署样例 | 降低环境漂移与交付摩擦 |

## 19. 配置注入责任边界表

| 层级 | 负责注入方 | 负责消费方 | 当前边界说明 |
|---|---|---|---|
| Root Workspace | 开发者 / CI | 所有仓库构建脚本 | 负责基础工具链与根命令入口 |
| API 进程 | 部署环境 / 本地 shell | `app/api` | 负责服务监听、数据根目录、运行时桥接命令 |
| Worker 进程 | 部署环境 / 本地 shell | `app/run-worker` | 负责 runRoot、runner image、资源规格、网络 |
| Run 级 runtime JSON | `app/run-worker` | `app/container-bridge` | 负责把业务输入转成运行时可执行配置 |
| Bridge 进程环境 | Docker / `node-pty` | `app/container-bridge` 与 Codex CLI | 负责 runId、workspaceId、targetPath、Codex 参数 |
| 前端构建变量 | Vite / Taro 构建环境 | Dashboard / Mobile | 负责公开 API 入口与平台差异 |
| 密钥类配置 | 未来 Secret Manager / Credential Broker | API / worker / bridge / MCP | 负责 API Key、Token、证书等敏感数据 |
