## 7. 本地回显能力缺口表

| 主题 | 当前情况 | 影响 | 正式要求 |
|---|---|---|---|
| optimistic message | 当前没有本地临时消息对象 | 依赖后端回流速度，无法保证 100ms | 发送时立即插入 `pending message bubble` |
| temp message id | 当前没有 | 无法在 ack/snapshot 时与本地消息对齐 | 增加 `client_message_id` |
| send queue | 当前没有 | 弱网下连续发送不稳定 | 增加 per-run 发送队列 |
| retry action | 当前没有失败气泡 | 用户无法重试单条消息 | 失败消息必须可重发 |

## 8. realtime 与 fallback 协同矩阵

| 主题 | 当前行为 | 当前问题 | 正式要求 |
|---|---|---|---|
| WS 可用 | 直接发 `runs.sendMessage` | 不消费 `runs.ack` | 以 ack 标记 `queued -> sent_to_gateway` |
| WS 不可用 | 直接走 HTTP | 用户看不见降级发生 | 显示“已切到 fallback” |
| SSE 模式 | 仍无法主动发消息，需 HTTP | transport 能显示但语义不完整 | 发送动作固定走 HTTP，并记录 telemetry |
| WS 发出后连接断开 | 当前无补偿逻辑 | 消息是否送达不可见 | 若无 ack/无 snapshot 回流，转 failed |

## 10. 消息状态机总表

| 状态 | 含义 | 进入条件 | 可流向 |
|---|---|---|---|
| `draft` | 本地未发送 | 用户正在输入 | `queued` |
| `queued` | 已点发送，待发出 | 点击发送后写入本地队列 | `sending`、`failed` |
| `sending` | 已发出，等待 ack 或 snapshot | WS 发包或 HTTP 请求发出 | `sent`、`failed` |
| `sent` | 已被服务端确认并进入消息流 | 收到 ack + snapshot，或 HTTP 返回成功 | 终态 |
| `failed` | 发送失败 | WS/HTTP 失败或超时 | `queued`、`discarded` |
| `discarded` | 用户主动删除失败消息 | 用户取消重试 | 终态 |

## 11. 失败场景矩阵

| 场景 | 当前行为 | 当前问题 | 正式行为 |
|---|---|---|---|
| WS 未连接 | 直接回退 HTTP | 用户无感知 | 记录降级并给出 inline transport 状态 |
| WS 发送后无回流 | 当前只清草稿 | 可能误判为成功 | 进入超时重试或 failed |
| HTTP 发送失败 | `mutation` 失败但无消息级 UI | 用户只看到按钮恢复可点 | 保留失败消息并支持重试 |
| 连续快速发送 | 当前无队列 | 依赖用户手速与网络稳定 | 串行或有限并发发送队列 |
| 切换实例时仍有待发消息 | 当前只有草稿，不跟踪待发消息 | 可能丢发送上下文 | 队列按 `runId` 隔离并可恢复 |

## 14. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无本地回显 | 发送结果依赖后端回流 | 无法保证 100ms 体验目标 | P0 |
| 无发送队列 | 网络波动时不稳定 | 多条消息连续发送风险高 | P0 |
| ack 未消费 | realtime 无显式确认语义 | 难判断送达边界 | P1 |
| 附件发送未接线 | “附件”按钮仅占位 | 核心业务链不完整 | P0 |
| 失败消息不可重试 | mutation 失败缺消息级状态 | 用户恢复能力不足 | P1 |
| 无幂等键 | 双击发送存在重复风险 | 数据一致性风险 | P1 |
