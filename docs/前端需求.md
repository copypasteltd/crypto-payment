## 2. 文档定位

本文档定义灵办词元前端体系的完整需求基线，覆盖以下内容：

- 用户侧对象模型与术语体系
- Web 与移动端信息架构
- 工坊、服务、任务、结果的页面结构
- 任务运行中的完整对话模式
- 文件、审批、通知、结果的前台组织方式
- 实时通信、状态模型、接口协作、缓存恢复
- 前端工程拆分、组件体系、验收标准

本文档作为前端主规范，目标是收敛以下历史偏差：

| 偏差 | 当前基线 |
|---|---|
| 用户侧直接暴露 `Session / Run / Trace` | 用户侧统一使用 `工坊 / 服务 / 任务 / 结果 / 我的资产` 表达 |
| 默认首页缺少任务服务分发能力 | 首页固定为工坊入口，承载真实服务分发能力 |
| 任务运行中页面以摘要卡片为主 | 任务运行页固定为完整对话工作面 |
| 启动前一次性收集全部业务参数 | 服务启动后立即创建任务，由 Codex 在对话中主动收集缺失信息 |

- Dashboard 的正式实现口径固定为 `React + Vite`。
- 小程序与移动端 H5 的正式实现口径固定为 `Taro` 一套工程多端输出。

- 任何新增第二工程、第二业务路由、第二样式主栈、第二状态主栈的提议，都必须先更新主文档并走架构评审。

## 3. 前端总体目标

### 3.1 业务目标

| 目标 | 说明 |
|---|---|
| 建立任务服务分发前台 | 以工坊和服务为中心组织平台供给侧能力 |
| 建立低门槛消费入口 | 轻度用户通过小程序或 H5 直接启动任务服务 |
| 建立持续任务工作面 | 用户可在任务页持续与 Codex 对话、补充信息、处理审批、消费文件 |
| 建立 Creator 生产前台 | Web 端支持 Creator 管理工坊、服务、Session、版本、发布 |
| 建立企业治理前台 | Web 端支持管理员管理凭证、策略、成员、审计、成本 |

### 3.2 体验目标

| 用户类型 | 体验目标 |
|---|---|
| 轻度用户 | 看到服务即可理解用途，启动路径控制在 3 到 5 步，任务执行通过自然对话推进 |
| 重度用户 | 能快速筛选工坊、服务、历史任务，处理失败和审批，直接消费结果 |
| Creator | 能清晰区分用户侧服务表达与底层 Session 资产表达 |
| 管理员 | 能在同一前台完成凭证、成员、策略、审计治理 |

### 3.3 前端范围

| 范围 | 包含内容 |
|---|---|
| 用户消费前台 | 工坊、服务、任务、结果、我的 |
| 重度用户前台 | 工坊工作区、实例工作区、批量启动能力 |
| Creator 前台 | Creator 工作区、服务配置、Session 版本、发布管理、调试回放 |
| 管理员前台 | Creator 工作区内的凭证、成员、策略、审计、成本治理 |
| 实时体验 | 对话流、审批、文件变化、结果通知 |

## 4. 当前设计基线

### 4.1 核心结论

| 编号 | 结论 | 说明 |
|---|---|---|
| 1 | 工坊是默认入口 | 首页承载真实任务服务分发，包含企业工坊、Creator 工坊、最近使用、推荐服务 |
| 2 | 服务是消费入口 | 用户点击服务进入详情与启动，不直接接触 Session |
| 3 | 启动即创建任务 | 服务启动后立即生成任务实例，直接进入任务对话页 |
| 4 | 任务页是完整对话工作面 | 用户与 Codex 是持续对话关系，审批、附件、文件、结果都进入消息流 |
| 5 | 结果在任务页与我的双入口沉淀 | 任务页即时消费，我的页长期管理 |
| 6 | 专业术语收敛到专业端 | `Session / Run / Trace / Runtime` 仅在 Creator、Debug、Admin 侧显式展示 |

### 4.2 设计原则

| 原则 | 说明 |
|---|---|
| 工坊优先 | 首页承载工坊、服务、标签、推荐和组织空间切换 |
| 术语分层 | 轻度用户只看到工坊、服务、任务、结果；专业端显示 Session、Trace、Version |
| 对话优先 | 任务运行中，对话是主界面，状态与附件围绕对话流组织 |
| 启动轻量化 | 启动页解释授权、风险和结果，不承载前置全量参数表单 |
| 结果双入口 | 结果文件在任务页即时可见，在我的资产中长期可见 |
| 组织化展示 | 企业私有工坊与 Creator 工坊需要显式区分 |
| 恢复连续性 | 用户离开任务页再进入时，滚动位置、未读状态、草稿内容可恢复 |

- `app/mobile` 内出现 `vite` 或 `@vitejs/plugin-react` 依赖，仅服务于 `@tarojs/vite-runner`，不构成独立 H5 Web 工程。
- 当前首发移动端验收只锁定 `build:h5`，`build:weapp / build:alipay` 保留为后续特化脚本。
- Dashboard 主栈必须包含 `react`、`react-dom`、`vite`、`@vitejs/plugin-react`、`react-router-dom`。

- Web 与 Taro 共享代码仅允许沉淀为类型、协议、纯函数与设计 token，不共享直接依赖 DOM 或 Taro API 的页面逻辑。

### 6.1 对象模型

## 9.5 任务对话页

### 页面定位

任务对话页是移动端最核心页面。该页面必须是完整对话模式，用户和 Codex 之间能够持续发送与接收消息。审批、附件、文件、进度、结果都通过对话流组织。

### 页面结构

| 区域 | 内容 |
|---|---|
| 顶部状态条 | 服务名、当前状态、文件数、耗时、返回按钮 |
| 页签切换 | 对话、文件、进度、结果 |
| 对话流 | 系统消息、Codex 消息、用户消息、审批卡片、附件卡片、文件卡片、结果卡片 |
| 固定输入区 | 文本输入、附件上传、发送按钮 |

### 消息类型

| 消息类型 | 来源 | 作用 | 必须支持的操作 |
|---|---|---|---|
| 系统消息 | 系统 | 展示任务创建、状态变化、授权完成、任务完成 | 展开、关闭 |
| Codex 文本消息 | Codex | 提问、解释、推进任务、反馈执行情况 | 复制、继续追问 |
| 用户文本消息 | 用户 | 补充信息、追问、说明 | 重发、编辑未发送草稿 |
| 审批卡片 | 系统 / Codex | 关键动作确认 | 确认、驳回、查看影响范围 |
| 附件卡片 | 用户 | 显示已上传文件 | 预览、删除未提交项、重传 |
| 文件卡片 | 系统 | 表示新文件生成 | 预览、下载、分享、转存 |
| 结果卡片 | 系统 | 表示结果包可消费 | 下载全部、再次运行 |
| 错误卡片 | 系统 / Codex | 表示失败、阻塞、风险 | 重试、查看原因 |

### 对话交互要求

| 编号 | 要求 |
|---|---|
| 1 | 进入页面默认定位到最新消息 |
| 2 | 输入框固定底部，软键盘弹起时不遮挡最新消息 |
| 3 | 用户发送消息后立即本地回显，再等待服务端确认 |
| 4 | 支持在输入区上传文件，上传完成后生成附件卡片 |
| 5 | 审批卡片进入消息流后，同时推送任务列表和通知提醒 |
| 6 | 文件生成后，消息流内出现文件卡片，文件页同步更新 |
| 7 | 切换页签后返回对话，恢复原滚动位置 |
| 8 | Codex 正在回复时，输入区允许继续输入，后续消息排队进入消息流 |
| 9 | 断线重连后补拉增量消息，避免重复渲染 |
| 10 | 未发送草稿与附件队列在异常退出后可恢复 |

### 文件、进度、结果页签要求

| 页签 | 说明 |
|---|---|
| 对话 | 默认主页签，承载完整对话 |
| 文件 | 显示当前任务所有输入与输出文件 |
| 进度 | 展示阶段状态、当前动作、审批状态、最近系统事件 |
| 结果 | 汇总最终结果包和可消费文件 |

## 14. 状态模型

|---|---|

| 文件列表 | 任务级缓存，随 `file.changed` 增量更新 |

| 禁止事项 | 禁止新增第二套 H5 工程、禁止引入第二套全局状态库、禁止在业务页面直接散落平台 API 调用 |

## 25. 任务对话工作面深度规范

## 25.1 工作面定位

任务页是整个平台的核心操作面。运行中的任务对用户表现为一个持续存在的对话对象，用户与 Codex 之间可以连续交换文本、文件、确认项和上下文说明。

## 25.2 对话布局规范

| 维度 | 移动端 | Web |
|---|---|---|
| 主信息轴 | 全屏消息流 | 中栏消息流 |
| 输入区 | 固定底部，软键盘上浮适配 | 固定底部，支持更丰富操作 |
| 文件与结果 | 通过页签切换 | 通过右侧栏常驻展示 |
| 状态信息 | 顶部状态条 + 页签 | 顶部筛选栏 + 右侧摘要 |
| 专业执行信息 | 摘要化 | 侧栏展示 |

## 25.3 消息分组规则

| 规则 | 说明 |
|---|---|
| 系统消息独立分组 | 不与用户或 Codex 普通消息混排 |
| 连续同源文本可折叠分组 | 连续 Codex 文本消息可做视觉归并 |
| 卡片消息独立成块 | 审批、附件、文件、结果卡片单独占行 |
| 时间分隔符按时间窗口插入 | 长时间无消息后需插入时间标签 |
| 未读锚点明确 | 回到任务页时定位首条未读 |

## 25.4 输入区规范

| 能力 | 必需性 | 说明 |
|---|---:|---|
| 文本输入 | 是 | 支持多轮持续对话 |
| 文件上传 | 是 | 支持文档、图片、表格、压缩包 |
| 草稿保留 | 是 | 按 `taskId` 隔离 |
| 本地回显 | 是 | 保证发送反馈即时性 |
| 发送队列 | 是 | 支持网络波动和多条待发送消息 |
| 引用回复 | Web 建议、移动端可选 | 用于复杂审批或多文件说明 |
| 快捷操作 | Web 可选 | 插入最近文件、引用上一轮、复制任务信息 |

## 25.5 滚动与未读规则

| 场景 | 规则 |
|---|---|
| 用户停留在底部 | 新消息到达自动滚动到底部 |
| 用户正在查看历史消息 | 新消息到达仅出现未读提示，不强制打断 |
| 从通知进入任务 | 直接定位到对应消息卡片 |
| 任务重新打开 | 恢复上次滚动位置，如存在未读则优先定位未读锚点 |
| 长消息流 | Web 端建议使用虚拟列表，移动端按分页加载历史消息 |

## 25.6 审批卡片交互规范

| 要求 | 说明 |
|---|---|
| 审批卡片插入消息流 | 审批请求必须可见于上下文位置 |
| 审批上下文可追溯 | 用户需看到审批前后相关消息 |
| 审批操作即时反馈 | 点击确认或驳回后先进入处理中状态 |
| 审批结果回写 | 成功后在消息流中回写审批结果消息 |
| 审批外溢提醒 | 任务列表、通知中心、状态条同步变更 |

## 25.7 附件与文件卡片交互规范

| 卡片类型 | 规则 |
|---|---|
| 附件卡片 | 上传成功后立即出现在用户消息后方 |
| 文件卡片 | 系统生成文件后立即插入消息流 |
| 文件定位 | 点击文件卡片可直接打开预览或跳转文件页签 |
| 结果卡片 | 任务完成时集中展示结果资产与再运行入口 |

## 25.8 任务完成态转换

| 阶段 | 页面行为 |
|---|---|
| 运行中 -> 已完成 | 顶部状态条更新，结果卡片插入消息流 |
| 结果生成中 | 文件卡片可先到达，结果卡片后到达 |
| 已完成后继续发问 | 允许用户继续对 Codex 提问，例如解释结果、要求再次导出 |
| 再运行 | 基于当前任务创建新任务实例 |
