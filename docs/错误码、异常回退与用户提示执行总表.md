## 2. 当前错误归一化主链矩阵

| 链路阶段 | 当前实现 | 输出 | 当前问题 |
|---|---|---|---|
| API route/service 抛错 | `throw AppError / ZodError / Error` | 原始异常 | 仅 API 层结构化较好 |
| API 统一错误处理 | `create-server.ts -> setErrorHandler(normalizeErrorPayload)` | `{ error: { code,message,details } }` | 无 requestId/traceId |
| WS 实时错误 | `socket-routes.ts -> sendRealtimeError()` | `runs.error` 仅带 message | 丢失 code/details |
| SSE | 连接前仍走 HTTP 错误归一化 | HTTP 错误对象 | 流内无独立错误帧 |
| SDK HTTP | `ensureOk()` 失败抛 `HTTP_<status>` | 字符串 Error | 丢失后端结构化错误 |
| SDK WS | `onError(string)` | 字符串 | 无错误域、无 retry 标识 |
| Dashboard / Mobile 页面 | `catch { return null }` 或 `showToast` | 静默回退或弱提示 | 页面层分类不足 |

## 3. API 错误出口执行矩阵

| 入口 | 当前出口 | 结构 | 当前回退 |
|---|---|---|---|
| `/v1/runs/*` HTTP | Fastify `setErrorHandler` | `error.code/message/details` | 统一 HTTP 返回 |
| `/ws/runs/:runId` 建连前 | `runs.error` + `socket.close(1008, reason)` | 仅 message | 关闭连接 |
| `/ws/runs/:runId` 消息处理期 | `runs.error` | 仅 message | 保持连接不断开 |
| `/v1/runs/:runId/stream` | 先经普通 HTTP handler | 标准 HTTP 错误对象 | 无流内错误帧 |
| `/internal/*` | 同 Fastify 错误处理 | 标准 HTTP 错误对象 | 供 bridge/worker 消费 |

## 4. HTTP 错误到前端行为矩阵

| 错误类型 | Dashboard 当前行为 | Mobile 当前行为 | 正式建议 |
|---|---|---|---|
| 参数错误 | 当前多由 mutation/query 异常中断 | 当前多被 `catch -> null` 吞掉 | 就地展示字段提示 |
| 资源不存在 | 依赖 fallback 数据或空态 | `tasks/detail` 回退到静态任务或空态页 | 404 专用空态 |
| 权限错误 | 当前未实现 | 当前未实现 | 路由级拦截 + 403 提示 |
| 文件读取失败 | 预览区提示“更适合下载” | 文件页多走空预览 | 区分权限/类型/不存在 |
| 创建实例失败 | 无统一提示规范 | `showToast("创建实例失败")` | 展示 code + 可重试动作 |

## 5. WebSocket 与 SSE 回退执行矩阵

| 场景 | Dashboard 当前行为 | Mobile 当前行为 | 正式建议 |
|---|---|---|---|
| 浏览器支持 WebSocket | 建立 WS，更新 Query Cache | 建立 WS，更新 Query Cache | 保持 |
| 无 WebSocket | 回退 SSE | 回退 SSE | 保持 |
| WS 已连接但 `sendMessage()` 不可用 | `runStream.sendMessage()` 返回 `false`，再回退 HTTP mutation | 同 Dashboard | 保持该双通道发送回退 |
| SSE 期间错误 | 当前无显式错误事件，只能断流 | 同 Dashboard | 增加流状态提示与重连策略 |
| WS 建连失败 | 当前仅 `onClose -> connected=false` | 同 Dashboard | 增加 error state 和重试退避 |

## 8. 错误提示粒度执行矩阵

| 层级 | 当前粒度 | 正式目标 |
|---|---|---|

## 9. 用户提示策略矩阵

| 错误域 | 终端提示方式 | 用户文案重点 |
|---|---|---|
| `VALIDATION_*` | 表单或输入框下方 inline | 指明哪一项缺失或非法 |
| `RUN_*` | 任务详情顶部 banner | 当前实例状态与可继续动作 |
| `FILE_*` | 文件面板局部空态 | 当前文件不可预览/不可下载原因 |
| `APPROVAL_*` | 对话流模块卡片 | 需要谁确认、确认后会发生什么 |
| `WORKSPACE_*` / `AUTH_*` | 页面级拦截页 | 当前空间不可访问或需重新登录 |
| `RUNTIME_*` / `MCP_*` | 对话流系统消息 + 管理台告警 | 运行链异常，需要等待或重试 |
| `QUOTA_*` | 强提示卡片 | 当前额度、超限原因、恢复路径 |

## 10. 重试与不可重试矩阵

| 场景 | 当前是否自动重试 | 正式建议 |
|---|---|---|
| HTTP 4xx 业务错误 | 否 | 不自动重试 |
| HTTP 5xx | 否 | query 可限次重试，mutation 不自动 |
| WS 建连失败 | 否 | 指数退避重连 |
| SSE 断开 | 否 | 自动重连并展示状态 |
| `readRunFile()` 文本预览失败 | 否 | 允许用户手动重试 |
| `createRun()` 失败 | 否 | 允许显式再次启动 |
| bridge health timeout | 不在前端层 | worker 侧限次重试 |

## 11. Query 层异常与空值回退矩阵

| Query | 当前异常处理 | 当前风险 |
|---|---|---|
| `liveTaskQuery` | `catch { return null }` | 无法区分 404/500/403 |
| Dashboard 文件预览 query | `catch { return null }` | 文本不可预览与接口失败被混淆 |
| run list / getRun | 多处依赖 SDK 默认抛错 | 缺集中 error boundary |

## 12. 内部链路错误传播矩阵

| 来源 | 当前传播路径 | 当前丢失信息 |
|---|---|---|
| `AppError` | API -> HTTP response | 无 requestId |
| `ZodError` | API -> HTTP/WS `message` | 无字段级 code |
| `bridge` 控制错误 | bridge HTTP -> worker -> API 多为原生 Error | 无统一 code |
| `api-sdk` | 结构化响应 -> `HTTP_<status>` | 丢失业务 code/message/details |
| `runStream` | WS error -> connected false | UI 无错误原因 |

## 13. 审计与观测补充矩阵

| 错误类型 | 需补充字段 | 作用 |
|---|---|---|

## 14. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| SDK 丢失结构化错误 | HTTP 非 2xx 只抛 `HTTP_<status>` | 双端无法分类处理 | P0 |
| WS 错误只有 message | code/details 丢失 | 实时链调试困难 | P0 |
| 页面层大量 `catch -> null` | 权限、404、500 被混淆 | 用户提示失真 | P1 |
| 无统一 error boundary | 各页面各自处理 | 交互一致性不足 | P1 |

## 17. 页面错误收口顺序表

| 阶段 | 动作 | 收口结果 |
|---|---|---|
| Phase 1 | 先把 SDK 改成结构化错误对象 | 页面能按错误域分流 |
| Phase 2 | 再把页面 `catch -> null` 改成分类错误态 | 权限/404/500 不再混淆 |
| Phase 3 | 再补 error boundary、toast/banner/modal 分层 | 交互提示统一 |
| Phase 4 | 最后把 runtime/bridge 错误接入前端提示链 | 用户可理解运行异常 |
