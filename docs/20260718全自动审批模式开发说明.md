# 全自动审批模式开发说明

## 1. 功能目标

每个 Agent 实例独立维护审批策略。用户可在 Dashboard 或移动端 H5 的对话发送区切换审批模式。开启后，实例内所有可审批请求自动通过；关闭后，后续请求恢复人工确认。

## 2. 状态模型

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `run.approvalMode` | `manual \| auto_all` | 当前实例审批模式，默认 `manual` |
| `run.approvalModeUpdatedAt` | ISO 8601 / `null` | 最近切换时间 |
| `run.approvalModeUpdatedByUserId` | User ID / `null` | 最近切换操作者 |
| `approval.decisionMode` | `manual \| auto_all \| null` | 单次审批的决策来源 |
| `approval.decidedByUserId` | User ID / `null` | 单次审批操作者或策略启用者 |

实例终止、容器重启和 API 重启后，审批模式从 Run 聚合记录恢复。历史实例缺少字段时按 `manual` 解析。

## 3. 覆盖范围

| 审批来源 | 自动模式行为 | 审计结果 |
| --- | --- | --- |
| Codex App Server 工具审批 | Bridge 立即返回 `accept` | 保存审批请求、自动决策、时间与关联资源 |
| 模式切换前的待审批 | API 逐项批准并等待 Bridge 确认 | 原审批记录更新为 `approved` |
| API 收到旧版 Bridge 的新审批 | API 根据实例策略回发批准命令 | 保存 `decisionMode=auto_all` |
| Run 创建配额例外 | 自动批准后继续启动 | 保存 quota override 与 Run approval |
| MCP 启动访问审批 | 自动批准后继续启动 | 保存 MCP 关联资源与自动决策 |
| 消息 Token 配额例外 | 当前请求内自动批准并继续发送 | 保存 quota override 与审批记录 |
| 上传存储配额例外 | 当前请求内自动批准并继续上传 | 保存 quota override 与审批记录 |
| 文件读取、预览、下载配额例外 | 当前请求内自动批准并继续处理 | 保存 quota override 与审批记录 |
| 下载票据配额例外 | 当前请求内自动批准并签发票据 | 保存 quota override 与审批记录 |

恶意文件、安全扫描拒绝、硬配额、权限校验、路径越界和网络治理拒绝保持强制阻断。这些结果不进入可审批请求集合。

## 4. API

### `PATCH /v1/runs/:runId/approval-mode`

请求体：

```json
{
  "approvalMode": "auto_all"
}
```

权限：工作区 `owner`、`admin`、`operator`。

处理顺序：

1. 校验 Run 与工作区权限。
2. 持久化实例审批模式、操作者和切换时间。
3. 写入系统会话消息并发布实时事件。
4. 开启自动模式时处理现有待审批。
5. Bridge 支持 `setApprovalMode` 时同步运行时策略。
6. 返回最新 `RunSnapshot`。

## 5. Bridge 协议

`RunControlCommand` 增加：

```json
{
  "type": "setApprovalMode",
  "payload": {
    "approvalMode": "auto_all"
  }
}
```

Codex 线程继续使用 `approvalPolicy: on-request`，保证每次敏感动作产生结构化审批事件。Bridge 根据实例策略响应 `accept` 或等待控制端决定。动态开启时，Bridge 排空内存中的待审批请求，并为每项请求发布已批准事件。

## 6. 前端交互

| 端 | 位置 | 控件 | 数据源 |
| --- | --- | --- | --- |
| Dashboard | 实例详情的对话发送框下方 | 开关、状态说明 | `RunSnapshot.run.approvalMode` |
| H5 | 任务详情的对话发送框下方 | Taro `Switch`、状态说明 | `RunSnapshot.run.approvalMode` |

切换请求执行期间禁用控件。成功后更新详情缓存并刷新实例列表；失败时保留服务端原状态并展示错误。实时审批卡片仅展示 `state=pending` 的记录。

## 7. 数据库迁移

迁移文件：`app/api/migrations/0032_run_approval_mode.sql`。

新增列：

| 列 | 约束 |
| --- | --- |
| `approval_mode` | 非空，默认 `manual`，限定 `manual/auto_all` |
| `approval_mode_updated_at` | 可空时间戳 |
| `approval_mode_updated_by_user_id` | 可空用户 ID |

## 8. 验收标准

1. 新实例默认人工审批。
2. Dashboard 与 H5 可独立切换当前实例。
3. 开启时当前待审批被批准，Codex 继续当前 Turn。
4. 开启后新增 Codex 审批不进入等待状态。
5. 消息、上传、读取、预览、下载和下载票据的软配额审批不要求重试。
6. 关闭后新增审批进入待确认状态。
7. 所有自动决策包含 `decisionMode=auto_all`、决定时间与操作者关联。
8. 其他实例的审批模式不受影响。
9. 硬配额、安全扫描、RBAC 与路径边界继续阻断。
10. API、Worker、Bridge、Dashboard、H5 重启后状态一致。
