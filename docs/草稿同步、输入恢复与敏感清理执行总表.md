## 5. 当前保存触发矩阵表

| 场景 | Dashboard | Mobile | 当前风险 |
|---|---|---|---|
| 文本变更 | `onChange -> setInstanceDraft()` | `onInput -> setTaskDraft()` | 每次输入都同步写存储，缺防抖 |
| 快捷动作注入 | 无 | `applyInlineDraft()` | 注入会直接覆盖原草稿 |
| 实时发送成功 | `runStream.sendMessage()` 成功即清理 | 同 Dashboard | 若服务端最终失败，本地草稿已丢失 |
| HTTP 发送成功 | mutation `onSuccess` 清理 | 同 Dashboard | 正常 |
| 页面离开 | 无额外动作 | 无额外动作 | 草稿无限期保留 |
| 工作区切换 | 当前仅切换 `currentWorkspaceId` | 同 Dashboard | 旧 workspace 草稿仍留在同一键空间 |

## 8. 正式草稿对象表

### 8.1 草稿主对象表

| 对象 | 主键 | 核心字段 | 说明 |
|---|---|---|---|
| `message_draft` | `draft_id` | `user_id`、`workspace_id`、`run_id`、`surface`、`draft_kind`、`content`、`updated_at`、`sensitivity_level` | 文本草稿主对象 |
| `draft_attachment_ref` | `draft_attachment_id` | `draft_id`、`file_id`、`source_type`、`mount_mode`、`order_index` | 草稿态附件引用 |
| `draft_context_snapshot` | `draft_id` | `last_route`、`last_path`、`last_module_action`、`client_version` | 恢复时辅助信息 |
| `draft_cleanup_event` | `event_id` | `draft_id`、`cleanup_reason`、`cleaned_at`、`triggered_by` | 清理审计 |

### 8.2 草稿类型表

| `draft_kind` | 含义 | 示例 |
|---|---|---|
| `message_text` | 普通对话输入 | “请继续执行并输出回执” |
| `approval_reply` | 针对审批模块的回复 | “我已确认当前待审批动作，请继续执行” |
| `error_recovery` | 针对错误恢复的回复 | “请先解释失败原因，再给我恢复建议” |
| `attachment_note` | 附件说明文字 | “这是 2026Q2 银行流水” |
| `workspace_file_ref` | 共享目录文件引用说明 | “请读取共享目录中的发票汇总” |

## 9. 草稿敏感级矩阵表

| 等级 | 内容范围 | 本地存储 | 云同步 | 清理策略 |
|---|---|---|---|---|
| `low` | 普通追问、创作偏好、操作指令 | 允许 | 允许 | 发送成功后清理，可保留最近历史副本 |
| `medium` | 业务说明、内部流程要求、审批偏好 | 允许 | 可选 | workspace 切换时隔离，不跨账号自动恢复 |
| `high` | 凭证、税号、支付信息、法务敏感说明 | 谨慎或禁持久化 | 禁止明文同步 | 关闭页面、登出、超时后强制清理 |

## 10. 命名空间与隔离表

| 维度 | 当前实现 | 正式要求 |

## 11. 恢复执行矩阵表

| 恢复场景 | 当前行为 | 正式行为 |
|---|---|---|
| 刷新当前任务页 | 按 `taskId/instanceId` 从本地恢复 | 先恢复本地，再按策略合并云草稿 |
| 路由跳到文件页再返回 | 草稿仍保留 | 保持 |
| 切换到另一个 run 再回来 | 各 run 独立草稿 | 保持，并记录 `last_run_id` |
| 工作区切换后回到旧工作区 | 当前同一 storage 池中仍可能读到旧草稿 | 仅在切回原 workspace 后恢复该空间草稿 |
| 登录到另一账号 | 当前无机制 | 必须清空不属于当前 `user_id` 的草稿 |

## 12. 清理触发矩阵表

| 触发条件 | 当前行为 | 正式建议 |
|---|---|---|
| HTTP 发送成功 | 清理 | 保留 |
| realtime 发送成功但未 ack | 不清理 | 已改为收到 server ack 后再清理 |
| 用户主动清空输入 | 无独立动作 | 支持“清空并删除草稿” |
| 工作区切换 | 不清理，只切换当前 workspaceId | 清理当前内存态，草稿按 workspace 分桶封存 |
| 登出 | 当前无 | 清理当前用户本地草稿缓存 |
| 高敏草稿超时 | 当前无 | 设置 TTL，到期清理 |
| run 完成并归档 | 当前无 | 视策略清理 message draft，保留审计记录 |

## 13. 正式接口表

| 方法 | 路径 | 主要参数 | 返回 | 作用 |
|---|---|---|---|---|
| `GET` | `/v1/me/drafts/runs/:runId` | `workspaceId`、`surface` | `message_draft[]` | 拉取当前 run 草稿 |
| `PUT` | `/v1/me/drafts/runs/:runId` | `draftKind`、`content`、`sensitivityLevel` | `message_draft` | 保存文本草稿 |
| `POST` | `/v1/me/drafts/runs/:runId/attachments` | `fileId`、`sourceType`、`mountMode` | `draft_attachment_ref` | 保存草稿态附件引用 |
| `DELETE` | `/v1/me/drafts/runs/:runId` | `draftId?` | `204` | 删除草稿 |
| `POST` | `/v1/me/drafts/runs/:runId/cleanup` | `reason` | `draft_cleanup_event` | 显式记录清理动作 |

## 16. 验收判定表

| 验收项 | 判定标准 |
|---|---|
| 草稿恢复正确 | 同一用户刷新页面后，可恢复同一 workspace / run 的正确草稿 |
| 草稿不串空间 | 切换 workspace 后不会读到其他空间草稿 |
| 高敏不外泄 | 高敏草稿不会以明文云同步，也不会在登出后残留 |
| 快捷注入可追踪 | 模块按钮生成的草稿能区分来源并可清理 |
| 发送清理可靠 | 只有消息真正被服务端接收确认后才清理本地草稿 |

## 17. 当前阻塞表

| 阻塞项 | 影响 | 优先级 |
|---|---|---|
| 草稿仅按 run/task id 索引 | 跨 workspace、跨用户隔离不足 | P0 |
| realtime 发送立即清理草稿 | 弱网或 ack 丢失时可能丢输入 | P0 |
| 附件/审批无正式草稿对象 | 无法恢复复杂输入现场 | P1 |
| Dashboard 缺消息模块快捷注入 | 双端交互能力不一致 | P1 |
