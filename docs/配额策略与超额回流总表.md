## 9. 超额回流状态机总表

| 状态 | 含义 | 进入条件 | 可流转 |
|---|---|---|---|
| `healthy` | 指标低于软阈值 | 默认状态 | `soft_warned`、`approval_pending`、`blocked` |
| `soft_warned` | 命中软阈值，允许继续 | 达到 soft limit | `healthy`、`approval_pending`、`blocked` |
| `approval_pending` | 已触发超额审批，等待用户/管理员处理 | `require_approval` 生效 | `approved_override`、`rejected_override`、`expired` |
| `approved_override` | 允许在本窗口继续执行 | 审批通过 | `healthy`、`blocked` |
| `rejected_override` | 拒绝继续，当前动作终止 | 审批拒绝 | `blocked` |
| `blocked` | 已达硬阈值或 override 失败 | `block` 生效 | `healthy` 仅在窗口重置或人工解除后 |
| `expired` | 审批超时未处理 | 超过审批有效期 | `blocked` |

## 10. 超额回流到对话链路总表

| 场景 | 系统注入方式 | 用户看到的内容 | Codex 行为 |
|---|---|---|---|
| 创建前即超额 | API 拒绝并返回结构化错误 | 页面提示额度不足 | 不创建 run |
| 运行中首次超额 | 追加 `system` 消息 + 待审批节点 | 当前额度状态、需要的确认动作 | 暂停推进，等待用户/管理员 |
| MCP 高风险调用超额 | 追加 `system` 消息 + 审批节点 | 告知外部能力额度或策略命中 | 暂停 connector 调用 |
| 浏览器提交前超额 | 追加 `system` 消息 + 审批节点 | 告知提交类动作需确认 | 保持当前上下文，等待批准 |
| Creator 发布超额 | 进入 release gate | 在 Creator 治理页显示超额 gate | 不激活发布 |

## 14. 当前缺口与补齐顺序表

| 优先级 | 缺口 | 影响 | 补齐动作 |
|---|---|---|---|
| P0 | 无 `quota_policy / quota_counter / quota_event` 正式表 | 无法执行正式配额 | 建 quota 域 |
| P0 | 创建 run、消息、下载、MCP 调用前未做统一校验 | 超额无法实时阻断 | 在 API 服务层建立统一 evaluator |
| P0 | 超额回流仅有产品语义，没有真实审批对象 | 额度治理无法闭环 | 建 `quota_override_request` 与 approval 绑定 |
| P1 | 前端未展示真实额度状态 | 用户看不到限额原因 | 在 Dashboard/H5 接入配额接口 |
