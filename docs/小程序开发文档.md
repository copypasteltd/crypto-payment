## 2. 开发定位

小程序 / H5 面向轻度用户、临时用户、企业一线人员。目标是让用户在看到服务后即可启动任务，并在任务对话中完成全部必要信息补充。

当前发布策略保持 `H5 first`，微信小程序构建与微信登录链路已进入可联调状态。支付宝小程序继续作为后续特化里程碑推进。微信环境配置与发布步骤见 `docs/微信小程序构建与登录配置.md`。

核心定位：

| 维度 | 目标 |
|---|---|
| 使用门槛 | 看到工坊即可开始，不需要理解 Session、Run、Trace |
| 核心流程 | 进入工坊 -> 选择服务 -> 启动任务 -> 在对话中补足信息 -> 获得结果 |
| 运行形态 | 任务详情页是完整对话工作面 |
| 资产沉淀 | 文件与结果回到任务详情和我的页双入口 |
| 空间语义 | 个人用户显示 `个人空间`，企业用户显示组织空间 |

### 2.1 Taro 冻结结论

| 维度 | 固定要求 | 工程意义 |
|---|---|---|
| 唯一正式工程 | `app/mobile` | 当前承接移动端 H5 首发交付，并为微信小程序、支付宝小程序保留同源扩展位 |
| 固定主栈 | `Taro 4.2.x + React 18.3.x + TypeScript 5.x` | 保持一套源码多端输出 |
| H5 归属 | `Taro H5 target` | H5 不新建第二套 `React + Vite` 移动端工程 |
| 业务路由 | `Taro Pages Router` | 页面注册、跳转、分享落点走统一机制 |
| 构建链 | `pnpm dev:h5 / build:h5` 为当前首发主链路，保留 `weapp / alipay` 开发与构建脚本 | 工程仍保持多端扩展能力 |
| 包管理与运行时 | `pnpm workspace + Node.js 22 LTS` | 与仓库共享包、根级脚本和 CI 环境保持一致 |
| 组件模型 | `Taro 页面 + React 函数组件 + Hooks` | 页面与消息工作面固定采用函数式实现 |
| 平台能力接入 | `Taro API + 项目适配层` | 页面层不直连 `wx`、`my`、`window` |
| 共享层边界 | 仅消费 `packages/*` | 不从 `app/dashboard` 导入页面、组件、hooks、stores |
| 禁止项 | `uni-app`、第二套 React H5 工程、`react-router-dom` 业务路由 | 防止多端实现分叉 |

### 2.2 Taro 技术栈执行摘要

| 项目 | 冻结要求 | 说明 |

| 组件模型 | `Taro 页面 + React 函数组件 + Hooks` | 不新增 class component、双轨页面模型或原生页内另起一套状态框架 |
| H5 归属 | `Taro H5 target` | H5 不单独创建 `React + Vite` 移动端工程 |

### 2.3 Taro 工程冻结条款

| 检查维度 | 固定要求 | 交付约束 |

| 正式脚本 | `dev:h5 / dev:weapp / dev:alipay / build:h5 / build:weapp / build:alipay` | `package.json` 必须直接表达 Taro 多端工程身份 |

| 路由归属 | `Taro Pages Router` | 页面跳转、分享落点、页面配置统一走 Taro 页面体系 |

| 平台能力 | `Taro API + 项目适配层` | 页面层不允许直接散落 `wx`、`my`、`window` 调用 |
| 环境变量 | `TARO_APP_API_BASE_URL`、`TARO_APP_ID` | API 基址与平台标识统一走环境注入 |
| 构建矩阵 | `h5 / weapp` | H5 与微信小程序构建均已通过；支付宝小程序进入后续特化范围 |
| CI 门禁 | 执行 `pnpm build:h5` 与 `pnpm build:weapp` | 两个当前交付目标均需保持可构建 |

### 2.5 Taro 端交付门禁

| 检查项 | 必须满足 | 不通过示例 |
|---|---|---|
| 工程身份 | `app/mobile` 仍是唯一正式移动端工程 | 新增平行 H5 React 工程或原生小程序工程 |
| 入口链 | `src/app.tsx`、`src/app.config.ts`、页面 `*.config.ts` 完整 | 跳过 Taro App 入口自行拼接页面壳 |
| 构建链 | `config/index.ts` 系列仍为唯一正式配置链 | 另起独立 `vite.config.ts` 作为移动端正式入口 |
| 多端输出 | 必须通过 `build:h5` 与 `build:weapp` | `build:alipay` 作为后续特化阶段验收项 |
| 路由边界 | 业务页面仍只走 `Taro Pages Router` | 在页面内并行维护 `react-router-dom` |
| 平台能力边界 | 上传、下载、分享、通知统一走 Taro 适配层 | 页面组件直接散落 `wx` / `my` / `window` 调用 |

开发约束：

- 任务页先展示多任务列表，用户点入后进入任务详情。
- 任务详情必须为完整对话工作面。
- `运行` 不能单独做底部导航页。
- `查看文件` 从任务详情进入，支持路径面包屑和路径输入。

## 6. 页面开发规范

### 6.1 工坊首页

#### 页面目标

- 做服务发现入口
- 区分企业工坊和 Creator 工坊
- 提升重复使用效率

#### 页面结构

| 区域 | 模块 |
|---|---|
| 顶部 | 当前空间、搜索、通知入口 |
| 推荐区 | 推荐工坊、最近使用、收藏服务 |
| 分类区 | 行业分类、任务类型、组织标签 |
| 列表区 | 服务卡片、筛选、排序 |

#### 样式要求

| 项目 | 要求 |
|---|---|
| 卡片 | 中密度，包含封面、标题、用途、状态标签 |
| 信息层级 | 先服务价值，再展示复杂度与耗时 |
| 主题 | 同时支持明暗两套主题 |

### 6.2 工坊详情

| 模块 | 内容 |
|---|---|
| 工坊头部 | 工坊名、简介、所有者、可见范围 |
| 服务筛选 | 分类、标签、排序 |
| 服务列表 | 服务卡片、最近启动标记、收藏状态 |

### 6.3 服务详情 / 启动页

#### 页面目标

- 解释服务作用
- 解释授权边界
- 立即启动任务

#### 页面结构

| 模块 | 内容 |
|---|---|
| 服务头部 | 名称、所属工坊、Creator、成功率、耗时区间 |
| 服务说明 | 适用场景、输出样例、限制说明 |
| 授权说明 | 需要的第三方授权、浏览器操作说明、风险提示 |
| 启动区 | 启动按钮、收藏、分享、预算提示 |

#### 启动规则

| 编号 | 规则 |
|---|---|
| 1 | 点击启动后立刻请求创建任务实例 |
| 2 | 创建成功后直接进入任务详情页 |
| 3 | 系统自动注入首条引导消息，让 Codex 询问缺失信息 |
| 4 | 不设置完整前置大表单 |
| 5 | 材料上传和额外信息补充放入任务对话阶段 |

### 6.4 任务列表

#### 页面目标

- 管理用户的多个任务 / 会话实例
- 快速找到待补充、待审批、运行中、已完成、失败任务

#### 页面结构

| 区域 | 模块 |
|---|---|
| 顶部 | 状态筛选、搜索、自定义标签、排序 |
| 中部 | 任务列表卡片 |
| 底部 | 保持底部导航常驻 |

#### 任务卡片字段

| 字段 | 说明 |
|---|---|
| 标题 | 服务名 + 业务标题 |
| 状态 | 待补充、待确认、运行中、已完成、失败 |
| 下一动作 | 例如“等待上传材料”“待确认付款” |
| 更新时间 | 最近消息时间 |
| 结果摘要 | 是否已生成文件、回执或结果包 |
| 未读数 | 新消息提醒 |

### 6.5 任务详情

任务详情页是移动端最核心页面。

#### 页面结构

| 区域 | 模块 | 要求 |
|---|---|---|
| 顶部摘要区 | 服务名、状态、标签、快捷操作 | 可折叠 |
| 顶部操作区 | 切换详情、查看文件、更多操作 | 与摘要区联动折叠 |
| 中部消息流 | 系统消息、Codex 消息、用户消息、审批卡片、文件卡片、结果卡片 | 主工作面 |
| 底部输入区 | 文本输入、上传、语音入口、发送 | 固定底部 |

#### 交互规则

| 编号 | 要求 |
|---|---|
| 1 | 用户可以与 Codex 多轮连续对话 |
| 2 | 审批卡片直接插入消息流并可当场处理 |
| 3 | 文件生成后作为消息卡片进入对话流 |
| 4 | 任务离开后返回需恢复滚动位置、未读位置、输入草稿 |
| 5 | 顶部摘要和操作菜单支持折叠与展开 |
| 6 | 失败状态需在消息流中清楚展示恢复建议 |

### 6.6 查看文件页

#### 页面目标

- 让用户直接访问当前任务工作路径
- 可切换到任意目标路径
- 可下载任务生成的任意文件

#### 页面结构

| 区域 | 模块 |
|---|---|
| 顶部 | 返回、当前任务名、下载统计 |
| 中部 | 文件树 / 文件列表、预览区、最近访问 |
| 底部路径栏 | 当前路径显示、路径选择、路径输入、常用路径快捷入口 |

#### 路径交互要求

| 交互点 | 要求 |
|---|---|
| 面包屑 | 可逐级返回上层目录 |

## 20. 2026-07-21 新建实例能力加载修复

### 20.1 故障结论

微信开发者工具中的新建实例页长期停留在“正在加载运行能力”。服务端访问日志显示登录会话刷新成功，Provider、MCP、MCP Binding 和 Credential 请求均未到达 Nginx。后端对应接口在 H5 调用中持续返回 `200`，故障位于微信端请求调度层。

React Query 默认使用浏览器在线状态控制请求。微信 WebView 可能使查询进入 `pending/paused`，此状态不会调用 `queryFn`。原页面同时使用 `isSuccess` 作为提交条件，导致按钮永久禁用；MCP 与 Credential 空态使用 `isLoading` 判断，又在 paused 状态下提前显示空数据。仅设置全局 `networkMode` 后，实际微信开发者工具仍出现首次查询未调度，因此新建实例页取消了能力加载阶段的 `useQuery` 依赖。

### 20.2 实现约束

| 模块 | 约束 |
|---|---|
| React Query | 微信环境统一使用 `networkMode: "always"`，H5 保持 `networkMode: "online"` |
| 新建实例能力加载 | 页面 `useEffect` 直接并发调用五个能力 API，使用 `idle/loading/success/error` 本地状态机 |
| Taro 请求 | `Taro.request` 统一设置 20 秒超时 |
| 提交条件 | Provider、Provider Binding、MCP、MCP Binding、Credential 全部成功后启用创建 |
| 加载状态 | 使用 `isPending` 表达首次加载和 paused 状态 |
| 错误状态 | 任一能力查询失败后停止加载文案，显示明确错误和“重新加载”入口 |
| 空状态 | 查询完成且无错误时才显示 MCP、Credential 空态 |
| Provider 状态 | 明确区分“加载中、加载失败、未配置、N 条路由” |
