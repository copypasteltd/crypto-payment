## 2. 当前审批事实矩阵

| 证据 | 当前实现 | 当前含义 | 当前缺口 |
|---|---|---|---|
| `createSeedApproval()` | run 创建时固定生成 1 条 `pending` 审批 | 每个 run 一创建就有初始审批对象 | 审批作用域过粗 |
| `RunApproval` 字段 | `approvalId/runId/prompt/state/requestedAt/decidedAt/note` | 当前审批对象最小可用 | 无 risk level、required role、scope |
| `runStatusTransitions` | `RUNNING -> WAITING_APPROVAL`、`WAITING_APPROVAL -> RUNNING/CANCELLED` | 状态机已允许审批态切换 | 当前创建 seed approval 时不自动切入 `WAITING_APPROVAL` |
| `RunsService.approve()` | 只处理首个 `pending` 审批 | 当前决策模型是“单实例取第一个待审批项” | 无指定 `approvalId` 的精确决策 |
| `ingestBridgeEvents()` | 接收 `approval.requested` 仅 upsert 审批对象 | Runtime 可以再动态追加审批请求 | 审批与状态变更没有强绑定 |

## 3. 实例创建时的审批播种执行矩阵

| 步骤 | 执行方 | 当前动作 | 输出 |
|---|---|---|---|
| 1 | 前端 | 发送 `CreateRunInput` | 实例化请求 |
| 2 | API | `createRunRecord()` 创建 `CREATED` run | run 基础记录 |
| 3 | API | `createInformationCollectionPrompt()` 生成首轮追问信息 | system prompt |
| 4 | API | `createSeedApproval()` 生成 1 条 `pending` 审批 | seed approval |
| 5 | API | `runsRepository.save()` 将 run、消息、文件、产物、审批一起写入 | 完整初始聚合 |
| 6 | API | 仅广播 `conversation.message` 事件 | 当前不会单独广播审批事件 |
| 7 | API | 异步 `runOrchestrator.startRun()` | 后续 runtime 启动 |

## 4. Runtime 发起审批请求执行矩阵

| 步骤 | 执行方 | 输入 | 当前动作 | 输出 |
|---|---|---|---|---|
| 1 | Codex / bridge | 高风险动作或业务中断点 | 产出 `approval.requested` 事件 | bridge event |
| 2 | Bridge -> API | `events[]` | 调 `POST /internal/runs/:runId/events` | API ingest |
| 3 | API | `ingestBridgeEvents()` | `upsertByKey(next.approvals, "approvalId", event.approval)` | 审批数组更新 |
| 4 | API | `#emitEvents(parsedEvents)` | 广播 `approval.requested` 相关事件 | WS/SSE 增量 |
| 5 | 前端 | 订阅到最新快照/事件 | 在对话中插入审批提示模块 | 用户进入审批交互 |

## 5. `approve()` 决策执行矩阵

| 执行点 | 当前实现 | 当前语义 |
|---|---|---|
| 待审批选择 | `current.approvals.find((approval) => approval.state === "pending")` | 总是取第一个待审批项 |
| 决策输入 | `ApproveRunInput.approved`、`note?` | 二元决策 + 备注 |
| 状态回写 | `approved -> RUNNING`，`rejected -> CANCELLED` | 当前审批直接控制实例继续或终止 |
| 审批对象回写 | 将目标审批改成 `approved/rejected`，写 `decidedAt/note` | 当前只更新命中的那一条 |
| 对话回写 | 追加 1 条 `system/approval` 消息 | 对话中保留决策痕迹 |
| 事件回写 | 广播 `run.status.changed` + `conversation.message` | 前端和 bridge 同步状态 |
| 运行侧命令 | `bridgeRegistry.dispatch(runId, { type: "approve", payload })` | 让运行侧恢复执行或结束 |

## 6. 决策结果输出矩阵

| 决策结果 | 审批状态 | run 状态 | 系统消息 | 运行侧后续动作 |
|---|---|---|---|---|
| 同意 | `pending -> approved` | `RUNNING` | `Approval granted. The run will continue.` | 继续执行 |
| 拒绝 | `pending -> rejected` | `CANCELLED` | `Approval rejected. The run has been stopped.` | 终止执行 |
| 重复提交同一审批 | 当前无显式冲突保护 | 取决于此刻是否仍能从 run 状态迁移 | 可能产生语义歧义 | 正式系统需拒绝 |
| 指定审批对象决策 | 当前不支持 | 不适用 | 不适用 | 正式系统需支持 `approvalId` |

## 7. 状态与审批数组的一致性矩阵

| 场景 | 审批数组状态 | run 状态 | 当前一致性 |
|---|---|---|---|
| 创建 run 后 | 已存在 `pending` 审批 | `CREATED` | 不一致 |
| runtime 发起审批且只发 `approval.requested` | `pending` 审批存在 | 可能仍停在 `RUNNING` | 不一致 |
| runtime 发起审批且同时发 `run.status.changed(WAITING_APPROVAL)` | `pending` 审批存在 | `WAITING_APPROVAL` | 一致 |
| 用户审批通过 | `approved` | `RUNNING` | 一致 |
| 用户审批拒绝 | `rejected` | `CANCELLED` | 一致 |

## 8. 当前前端回流呈现矩阵

| 终端 | 当前入口 | 当前呈现方式 | 当前结论 |
|---|---|---|---|
| Dashboard 实例页 | run 详情页 / 实时页 | 通过状态、消息、后续建议动作呈现审批上下文 | 已在实例对话主视图内承载 |
| Mobile 任务页 | 任务对话页 | `buildModuleMessages()` 可插入审批卡，与对话消息并列 | 符合“完整对话模式中处理审批”的要求 |
| Creator 治理页 | 凭证/成员/策略/审计/成本分区 | 展示治理约束，但不直接处理单实例审批提交 | 当前是治理视图，不是 run 决策入口 |

## 9. 治理分区与审批联动矩阵

| 治理分区 | 当前界面语义 | 对审批的正式联动要求 | 当前状态 |
|---|---|---|---|
| `credentials` | 哪些 secret mount、哪些 connector ref、哪些需要轮换 | 高敏凭证首次使用、越权使用、轮换前使用都可触发审批 | 仅 UI 语义 |
| `members` | 谁能看、谁能发、谁能审 | 审批需要按角色与工作区绑定 | 仅 UI 语义 |
| `policy` | 浏览器敏感动作、路径白名单、容器销毁 | 提交、支付、删除、越权路径等必须回流审批 | 部分路径边界已生效 |
| `audit` | 脱敏、回放、导出 | 审批结果、审批人、审批上下文必须进入审计账本 | 当前缺正式审计域 |
| `cost` | 配额、外部 API 调用、超额回流 | 超预算、超额度、超风险资源使用需回流审批 | 当前缺正式计费配额域 |

## 10. 正式审批对象扩展字段矩阵

| 字段 | 类型 | 作用 |
|---|---|---|
| `approval_request_id` | string | 请求主键 |
| `approval_scope` | `browser-submit / payment / path-write / connector-egress / quota-overage / publish-release / other` | 明确审批范围 |
| `risk_level` | `low / medium / high / critical` | 驱动前端提示与审批角色 |
| `required_role` | string | 指定可决策角色 |
| `resource_ref` | object | 指向 run、connector、credential、file、release |
| `requested_by_actor` | object | 标明是 runtime、policy engine 还是 creator gate 发起 |
| `decision_token` | string | 防重复决策与幂等提交 |
| `audit_event_id` | string | 绑定审计账本 |

## 11. 正式审批回流链路矩阵

| 场景 | 发起点 | 回流到哪里 | 需要补齐的正式域 |
|---|---|---|---|
| 浏览器提交报税 | runtime | run 对话页 + audit | approval + audit |
| 第三方 MCP 首次出网 | connector policy | run 对话页 + governance | approvals + connectors |
| 图像额度超限 | quota engine | run 对话页 + cost 面板 | quotas + billing |
| session 包发布激活 | release gate | Creator 审核页 | releases + gates |
| 下载敏感导出包 | audit export | Dashboard 实例页 / audit 页 | audit + files |

## 12. 当前不一致与修复动作矩阵

| 问题 | 当前表现 | 修复动作 | 优先级 |
|---|---|---|---|
| seed approval 已创建但 run 不进 `WAITING_APPROVAL` | 创建后审批语义悬空 | 定义 seed approval 是否只是引导型提示；若是强审批则同步切状态 | P0 |
| `approval.requested` 不强制拉起审批状态 | 审批数组与状态可能脱节 | 规定 `approval.requested` 的状态联动策略 | P0 |
| `approve()` 不指定 `approvalId` | 多审批场景只能取首个 pending | `ApproveRunInput` 增加 `approvalId` | P0 |
| 缺风险级与作用域 | 审批粒度只有 yes/no | 扩展正式审批对象 | P1 |
| 缺审计账本绑定 | 审批结果只在 run 快照里 | 落正式审计域 | P1 |

## 13. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 审批域尚未独立 | 全部混在 `runsService` | 无法支撑复杂审批与治理流程 | P0 |
| 决策幂等缺失 | 无 `approvalId` + token | 多端重复点击难治理 | P0 |
| 治理页无后端约束力 | Creator 只展示不执行 | 平台治理不能落到 runtime | P0 |
| 超额与高风险审批未接入策略引擎 | 只有单一人工审批动作 | 无法满足企业场景 | P1 |

## 14. 当前已验证执行事实表

| 事实 | 当前证据 | 当前结论 |
|---|---|---|
| 实例创建时一定会播种 1 条 `pending` 审批 | `app/api/src/modules/runs/service.ts#createSeedApproval` | 审批对象已进入 run 聚合初始快照 |
| 播种审批不会自动把 run 推进到 `WAITING_APPROVAL` | `RunsService.createRun()` | 当前审批数组与 run 状态在创建时存在语义脱节 |
| `approve()` 只会处理第一条 `pending` 审批 | `RunsService.approve()` | 现阶段不支持多审批并行决策和精确 `approvalId` 定位 |
| runtime 回流的 `approval.requested` 只会 upsert 审批数组 | `RunsService.ingestBridgeEvents()` | 审批追加与 run 状态切换没有强绑定规则 |
| 前端对审批的直接动作尚未真正落接口 | `app/mobile/src/lib/liveTaskAdapters.ts`、`app/dashboard/src/pages/instances/InstancesPage.tsx` | Mobile 以写草稿为主，Dashboard 仍以普通对话输入为主 |

## 16. 收口顺序表

| 顺序 | 动作 | 目标模块 |
|---|---|---|
| P0 | 为审批对象和决策接口补齐 `approvalId`、幂等 token、作用域字段 | `packages/contracts`、`app/api`、`packages/api-sdk` |
| P0 | 规定 `approval.requested` 与 `WAITING_APPROVAL` 的强绑定状态机 | `packages/domain-models`、`app/api` |
| P0 | 在双前端补齐真正的审批直连动作与处理中态 | `app/mobile`、`app/dashboard` |
| P1 | 将审批写入正式审计账本，并接入治理、配额、凭证、MCP 策略 | `app/api`、治理域 |
| P1 | 让 Creator 治理分区产出的策略能够驱动 runtime 审批触发 | `app/dashboard`、`app/api`、`app/run-worker` |
