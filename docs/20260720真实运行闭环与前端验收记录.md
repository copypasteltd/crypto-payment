### 2.2 MCP 注入与审批

| 环节 | 实现 |
|---|---|
| 注册表校正 | 启动时校正平台托管 MCP；保留工作区和第三方 MCP 条目 |
| Playwright 默认条目 | 使用真实 Runner 可执行路径，状态为 active，不要求伪凭证和伪网络策略 |
| Image MCP | 缺少真实 Helper 时保持 disabled，禁止以假可用状态进入 Run |
| Codex 配置 | Bridge 将已解析 MCP 转换为 Codex 原生 `mcp_servers` 配置，并随 `thread/start` 发送 |
| 启动状态 | 处理 `mcpServer/startupStatus/updated`，保留 ready/failed 证据 |
| 调用审计 | 原生 MCP item 与审计日志统一映射为 MCP Call Audit，按 Call ID 去重 |
| 手工审批 | `mcpServer/elicitation/request` 映射为 `mcp-access` 审批 |
| 自动审批 | `approvalMode=auto_all` 自动接受 MCP 工具请求和受支持的表单请求 |
| 脱敏 | MCP 参数、结果和错误摘要执行敏感键与 Token 脱敏 |

### 2.3 Worker API 边界

| 调用方向 | Base URL |
|---|---|
| 宿主机 Worker 下载 Session Pack | `LINGBAN_API_BASE_URL`，HZ01 为 API 宿主机地址 |
| 容器 Bridge 回调 API | `LINGBAN_RUNTIME_API_BASE_URL`，容器使用 `host.docker.internal` |
| 前端公共 API | HTTPS 公网反代地址 |

Worker 禁止使用容器回调地址执行宿主机下载。连接失败日志包含 HTTP 方法、脱敏 URL 和底层 cause。

### 2.4 PostgreSQL 写入一致性

Creator 与 Workshop Catalog Repository 已将普通实体更新从全表删除重写改为实体级 UPSERT。Workshop 与 Service 写入、发布激活写入使用事务；Launch Template 删除按业务键精确执行。并发写入不会清除其他用户、工作区或 Package 的数据。
