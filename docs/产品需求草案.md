## 2. 产品概述

灵办词元是一个面向 agent 执行业务流程复用的平台。平台将一次成功运行的 agent session 作为可继承运行资产，通过脱敏、变量绑定、环境封装和云端运行，使用户能够在移动端或 Web 端快速启动同类任务。

产品采用双端架构：

| 端侧 | 面向用户 | 核心目标 | 复杂度暴露 |
|---|---|---|---|
| 小程序 / 移动端 H5 | 轻度用户、临时用户、企业一线人员 | 快速选择任务、填写信息、授权、查看进度、获取结果 | 低 |
| Web Dashboard | 重度用户、Creator、企业管理员、运营人员 | 创建 session、管理任务、审计运行、调试失败、维护版本、配置权限 | 高 |

产品对终端用户呈现为任务服务平台。用户无需理解 agent、session、trace、runtime 等内部概念，只需要选择服务、填写必要信息、完成授权并等待结果。

系统内部采用 Session Fork Runtime。每次用户启动任务时，系统从已发布的 session 模板派生一个云端运行实例，绑定用户输入和授权信息，执行对应业务流程，并记录完整执行账本。

## 3. 产品目标

### 3.1 业务目标

| 目标 | 描述 |
|---|---|
| 降低 agent 工作流使用门槛 | 轻度用户可通过小程序或移动端 H5 直接启动复杂 agent 任务 |
| 复用成功执行经验 | 将已跑通的 session 作为可继承资产，降低重复业务流程的执行成本 |
| 支持 Creator 分发能力 | 允许 Creator 录制、配置、测试、发布可复用 session 服务 |
| 支持企业治理 | 提供权限、密钥、成本、审计、私有任务库等企业级能力 |
| 建立 session 资产市场 | 逐步形成可搜索、可运行、可度量、可维护的 agent session 服务库 |

### 3.2 用户体验目标

| 用户类型 | 体验目标 |
|---|---|
| 轻度用户 | 看到任务即可使用，首次启动流程控制在 3 到 5 步 |
| 重度用户 | 支持批量运行、历史复用、失败重试、结果管理 |
| Creator | 支持录制 session、配置 slot、测试 fork、发布版本、查看运行指标 |
| 企业管理员 | 支持成员管理、权限治理、密钥托管、成本控制、审计导出 |

## 4. 核心概念定义

| 概念 | 定义 | 面向用户是否展示 |
|---|---|---|
| Task / 服务 | 面向用户展示的可执行任务，例如“短剧自动生成”“发票整理” | 展示 |
| Session | 一次完整 agent 执行过程，包含对话、工具调用、文件变化、浏览器操作等 | 仅 Web 专业端展示 |
| Trace | session 执行过程中产生的事件流 | 仅 Web 专业端展示 |
| Slot | session 中需要由新用户提供或替换的变量字段 | 移动端以表单字段展示 |
| Fork | 基于已发布 session 创建新的派生运行实例 | 用户侧不展示术语 |
| Runtime Snapshot | 支撑 session 复用的运行环境快照 | 不向轻度用户展示 |
| Execution Ledger | 每次运行的审计记录、成本记录、输出记录和确认记录 | 移动端展示摘要，Web 展示完整记录 |
| Creator | 创建、维护、发布 session 服务的用户 | Web 端展示 |

## 7. 移动端产品设计

### 7.1 移动端定位

小程序和移动端 H5 面向轻度用户，目标是让用户在最短路径内完成任务启动和结果获取。移动端不暴露内部技术细节，不展示原始 session、trace、runtime 配置和工具调用细节。

### 7.2 移动端页面结构

| 页面 | 核心内容 | 关键操作 |
|---|---|---|
| 首页 | 搜索任务、推荐任务、最近使用、企业任务、分类入口 | 搜索、筛选、进入任务 |
| 任务详情页 | 服务说明、输入要求、预计费用、预计耗时、所需授权、成功率、示例结果 | 立即使用、收藏、分享 |
| 启动页 | 服务说明、授权要求、成本上限、预计耗时、风险动作说明 | 确认启动、返回修改 |
| 任务对话页 | 系统引导消息、文件上传、图片上传、API Key 输入、账号授权、补充说明、草稿恢复 | 发送消息、上传、继续补充、批准关键动作 |
| 运行中页面 | 阶段进度、当前动作摘要、已耗时、预计剩余时间、等待确认提示 | 查看详情、处理确认、继续对话 |
| 关键动作确认页 | 动作摘要、数据摘要、影响范围、风险说明 | 确认、修改输入、拒绝、联系支持 |
| 结果页 | 输出预览、文件下载、分享链接、再次运行、复制任务 | 下载、分享、再运行 |
| 我的任务 | 运行中、已完成、失败、待确认、草稿 | 查看、筛选、重试、删除记录 |

### 7.3 移动端核心流程

```text
看到任务卡片
-> 点击立即使用
-> 确认费用和耗时
-> 启动云端 agent
-> 系统注入引导消息
-> 在任务对话中补齐必要信息
-> 完成授权
-> 查看阶段进度
-> 处理关键确认
-> 获取结果
-> 进入历史记录
```

### 7.4 移动端任务卡片字段

| 字段 | 示例 | 说明 |
|---|---|---|
| 任务名称 | 短剧自动生成 | 用户第一识别信息 |
| 适用场景 | 输入题材后自动生成剧本、分镜和视频任务 | 简要说明服务能力 |
| 预计耗时 | 约 18 分钟 | 降低等待不确定性 |
| 费用 | 预计 ¥xx 起 | 支持预算判断 |
| 成功率 | 92% | 来自历史运行统计 |
| 所需授权 | Seedance API Key | 提前暴露授权成本 |
| 输出类型 | 剧本、分镜、视频链接 | 明确交付结果 |
| 操作按钮 | 立即使用 | 主行动入口 |

### 7.5 移动端交互组件

| 组件 | 功能 | 设计要求 |
|---|---|---|
| Task Card | 展示可启动任务 | 信息密度低，重点突出任务名、耗时、费用、成功率 |
| Slot Form | 收集必要输入 | 分步表单、自动校验、支持草稿 |
| File Uploader | 上传图片、文档、表格、素材包 | 支持断点、格式校验、大小提示 |
| Authorization Sheet | 授权账号、API、文件权限 | 明确展示授权范围和撤销方式 |
| Progress Timeline | 展示任务阶段进度 | 阶段级展示，避免技术日志 |
| Approval Sheet | 处理关键动作确认 | 使用底部弹窗或通知卡片，突出影响范围 |
| Result Package | 展示和分发结果 | 支持下载、分享、再运行、复制任务 |
| Failure Card | 展示失败原因 | 展示业务原因、可操作建议、重试入口 |

### 7.6 移动端不展示内容

| 内容 | 原因 |
|---|---|
| 原始 Session Trace | 信息密度过高，不适合轻度用户 |
| Tool Call 明细 | 技术细节过多 |
| Prompt / System Context | 不适合终端用户理解 |
| Runtime 配置 | 与用户目标无直接关系 |
| 浏览器调试画面 | 移动端观看成本高 |
| 版本 Lineage 细节 | 属于 Creator 和运维关注点 |
| 脱敏规则配置 | 属于资产生产和治理能力 |

## 8. Web Dashboard 产品设计

### 8.1 Web Dashboard 定位

Web Dashboard 面向重度用户、Creator、企业管理员和运营人员，承载工坊分发、实例协作、Creator 生产、调试回放、权限治理和审计能力。当前产品基线采用 `工坊 / 实例 / Creator` 三大一级工作区，调试、治理、批量能力进入对应工作区内部，不再单独设为一级入口。

### 8.2 Web 工作区结构

| 工作区 | 面向用户 | 核心能力 | 内部子区 |

## 9. 核心业务流程

### 9.1 轻度用户任务执行流程

| 步骤 | 用户动作 | 系统动作 | 输出 |
|---|---|---|---|
| 1 | 打开小程序/H5 | 加载推荐工坊、企业工坊、最近使用 | 工坊首页 |
| 2 | 选择服务 | 加载服务说明、授权要求、输出样例 | 服务详情 |
| 3 | 点击立即启动 | 立即创建任务实例并分配云端运行环境 | 任务实例 |
| 4 | 进入任务对话 | 系统自动注入首条引导消息，请 Codex 询问缺失信息 | 对话起点 |
| 5 | 按对话补充材料 | 用户通过消息、上传、授权完成信息补充 | 有效业务输入 |
| 6 | 处理授权与确认 | 绑定凭证引用、写入确认记录 | 授权状态与确认记录 |
| 7 | 查看执行过程 | 云端 agent 持续执行并回传消息、文件、阶段信息 | 对话流与过程状态 |
| 8 | 处理中途审批 | 将审批卡片插入消息流，用户就地确认 | 审批记录 |
| 9 | 查看并下载结果 | 沉淀文件、回执、结果包、执行账本摘要 | 结果包 |

### 9.2 Creator 发布服务流程

| 步骤 | Creator 动作 | 系统动作 | 输出 |
|---|---|---|---|
| 1 | 创建 session 项目 | 初始化项目空间 | 项目 ID |
| 2 | 启动录制 | 开启 trace recorder | 原始 trace |
| 3 | 完成一次成功执行 | 记录对话、工具调用、文件变更、浏览器动作 | 成功 session |
| 4 | 标记敏感字段 | 生成 redaction map 和 slot schema | 脱敏 session |
| 5 | 配置 slot | 定义字段类型、校验规则、默认值、示例值 | 移动端表单结构 |
| 6 | 测试 fork | 使用测试数据创建派生实例 | 测试运行记录 |
| 7 | 修正问题 | 调整 slot、授权、环境依赖 | 可发布版本 |
| 8 | 发布服务 | 写入任务库和版本记录 | 上架任务 |
| 9 | 维护版本 | 查看失败记录、修复漂移、发布新版本 | 版本 lineage |

### 9.3 重度用户批量运行流程

| 步骤 | 用户动作 | 系统动作 | 输出 |
|---|---|---|---|
| 1 | 选择任务 | 加载任务 schema | 批量配置页 |
| 2 | 上传 CSV/表格 | 解析字段和样本数据 | 字段预览 |
| 3 | 映射字段 | 校验每列和 slot 的对应关系 | 字段映射 |
| 4 | 配置并发和预算 | 计算预计成本和资源需求 | 批量运行计划 |
| 5 | 启动批量任务 | 创建多个 forked session | 批量任务组 |

## 10. Session Fork Runtime 需求

### 10.1 核心运行链路

```text
选择任务
-> 获取已发布 session 版本
-> 校验用户输入和授权
-> 绑定 slot
-> 创建 runtime workspace
-> 恢复运行环境
-> 创建 forked session
-> 启动 agent runner
-> 执行任务
-> 写入 execution ledger
-> 生成结果包
-> 通知用户
```

### 10.2 核心模块

| 模块 | 职责 | 关键产物 |
|---|---|---|
| Trace Recorder | 记录 agent 消息、工具调用、浏览器事件、文件 diff、stdout/stderr | Immutable Trace |
| Redaction Engine | 识别并替换敏感字段，生成变量映射 | Redaction Map、Slot Schema |
| Session Forker | 基于已发布 session 创建派生实例 | Forked Session |
| Slot Binder | 将用户输入绑定到 session 占位符 | Bound Input |
| Cloud Runner | 在隔离容器中执行 agent 实例 | Running Instance |
| Credential Vault | 托管和注入密钥、OAuth、账号凭证 | 临时凭证引用 |
| State Validator | 校验页面、API、文件状态是否符合执行预期 | 状态校验结果 |
| Execution Ledger | 记录运行状态、确认动作、工具调用、成本和结果 | 审计账本 |
| Result Packager | 整理输出文件、链接、报告、视频等交付物 | Result Package |
| Notification Service | 推送运行状态、待确认动作、完成通知 | 微信/短信/企业微信/飞书通知 |

## 17. 当前建议

在完整系统目标不变的前提下，首阶段建议采用以下策略：

| 维度 | 建议 |
|---|---|
| 端侧 | 移动端 H5 优先，小程序作为第二入口 |
| 场景 | Seedance API 短剧生成优先 |
| Runtime | 早期绑定单一 agent runtime |
| 用户侧体验 | 隐藏 session 概念，使用“任务/服务/运行记录/结果”表达 |
| Web 侧能力 | 先做任务管理、slot 配置、运行记录、基础 trace |
| 安全策略 | API Key 托管、运行容器隔离、关键动作确认、execution ledger |
| 成功标准 | 轻度用户能在 3 到 5 步内启动任务，并成功获取结果 |

对应前端工程固定采用以下实现约束：

| 端 | 固定实现方式 | 工程路径 | 工程约束 |
|---|---|---|---|
| Web Dashboard | `React 18.3.x + Vite 5.x + TypeScript 5.x` | `app/dashboard` | 重度用户与 Creator 的唯一正式 Web 前端 |
| 小程序 / H5 | `Taro 4.2.x + React 18.3.x + TypeScript 5.x` | `app/mobile` | 移动端首发先交付 H5，后续在同一套工程内扩展微信小程序、支付宝小程序特化 |
| 共享层 | `pnpm workspace + packages/*` | 仓库根目录 | 类型、协议、设计 token、纯函数统一沉淀，禁止复制式双写 |
| 运行时与包管理 | `Node.js 22 LTS + pnpm workspace` | 仓库根目录 | 前端依赖安装、脚本执行、共享包链接统一基线 |
| 样式主题层 | `@lingban/ui-tokens + CSS Variables` | `packages/ui-tokens` + 各端样式层 | 两端共用统一主题源，不并行维护第二套样式主栈 |

补充工程冻结矩阵：

| 维度 | Dashboard | 小程序 / H5 | 约束 |
|---|---|---|---|
| 启动入口 | `src/main.tsx` | `src/app.tsx` + `src/app.config.ts` | 两端启动壳分开治理 |
| UI 主栈 | `React + React DOM` | `Taro + React` | Web 与移动端运行时边界固定 |
| 组件模型 | `React 函数组件 + Hooks` | `Taro 页面 + React 函数组件 + Hooks` | 统一函数式页面实现，不并行维护第二组件模型 |
| 路由栈 | `React Router` | `Taro Pages Router` | 不混用业务路由体系 |
| 构建产物 | `Vite dist` | `Taro h5` 首发，保留 `weapp / alipay` 扩展输出位 | H5 仅由 Taro 输出 |
| 正式命令 | `pnpm dev / build / lint / preview` | `pnpm dev:h5 / dev:weapp / dev:alipay / build:h5 / build:weapp / build:alipay` | 命令即工程身份，不引入平行脚本语义 |
| 多语言 | `zh-CN`、`en-US` 首发 | 中文首发，保留扩展位 | Dashboard 先承担正式双语面 |
| 平台能力 | Web 适配层封装 | Taro 适配层封装 | 页面层禁止散落平台 API |
| 禁止项 | `Next.js`、`Umi`、`Remix`、`@tarojs/*` 页面运行时 | `uni-app`、第二套 React H5 工程、`react-router-dom` 业务路由 | 防止端间漂移与工程边界失控 |

前端工程治理补充：

| 治理维度 | 固定结论 |
|---|---|
| Web 主前端 | 只有 `app/dashboard`，固定采用 `React + Vite` |
| 移动端主前端 | 只有 `app/mobile`，固定采用 `Taro` 一套工程首发输出 H5，后续扩展 Weapp / Alipay |
| H5 归属 | H5 固定归属 `Taro H5 target`，不独立创建第二套移动端 React Web 工程 |
| 共享层 | 共用逻辑统一沉淀到 `packages/*`，不在两个前端工程之间直接复制页面实现 |
| 脚本语义 | Dashboard 脚本围绕 `vite`；移动端脚本围绕 `taro build --type ...` | `package.json` 层面即体现主栈边界 |
| 交付门槛 | Dashboard 至少通过 `pnpm build`，移动端当前至少通过 `pnpm build:h5` |

当前仓库内前端共享层固定收口如下：

| 共享包 | 作用 | 约束 |
|---|---|---|
| `@lingban/contracts` | 协议 schema 与类型 | 前后端统一来源 |
| `@lingban/domain-models` | 任务快照、领域投影、纯函数适配 | 两端共用，不承载页面实现 |
| `@lingban/api-sdk` | 统一 API SDK | 页面层统一走 SDK，不散落请求实现 |
| `@lingban/ui-tokens` | 设计 token | Dashboard 与 Taro 端共用主题源 |

补充约束：

- Dashboard 固定采用 `React + Vite + React Router`，不引入 `Next.js`、`Umi`、`Remix` 等替代框架。
- 小程序与 H5 固定采用 `Taro` 一套工程输出，构建链固定为 `Taro CLI + Vite Runner`，不创建第二套移动端 React 工程。
- `app/dashboard/package.json` 只允许表达 `dev / build / lint / preview` 这类 React + Vite 主链路命令。
- `app/mobile/package.json` 只允许表达 `dev:* / build:*` 这类 Taro 多端命令，H5 通过 `build:h5` 与 `dev:h5` 输出。
- `app/mobile` 内存在 `vite` 相关依赖，仅服务于 `@tarojs/vite-runner`，不改变 H5 归属为 `Taro H5 target` 的事实。
- `app/mobile` 中若保留 `plugin-platform-tt / swan / jd / qq / harmony-hybrid` 等模板平台插件，仅视为扩展位，不纳入当前正式交付矩阵。
- 前端正式代码固定使用 `TypeScript`，状态管理固定使用 `TanStack Query + Zustand`。
- 两端主题层固定采用 `@lingban/ui-tokens + CSS Variables`，未经评审不新增第二套样式主栈。
- Web 与移动端共享层仅沉淀类型、协议、纯函数、设计 token，不共享页面级实现。

前端技术路线冻结补充：

| 场景 | 必须落位工程 | 固定主栈 | 禁止做法 |
|---|---|---|---|
| 重度工作台、Creator、治理、审计、多语言后台 | `app/dashboard` | `React + Vite` | 新建第二个 Web 主前端工程，或将 Taro 页面运行时混入 Dashboard |
| 轻度用户启动、任务对话、文件浏览、我的页、移动端 H5 | `app/mobile` | `Taro + React` | 为 H5 再维护一套 `React + Vite` 移动端工程 |
| 跨端协议、SDK、纯函数、设计 token | `packages/*` | `pnpm workspace` 共享层 | 在两端页面中复制协议与通用实现 |
| 交付验收 | `Dashboard build` 与当前 `Taro h5 build` | 构建成功作为最小交付门槛 | H5 首发阶段不得以未来小程序脚本替代当前验收 |
