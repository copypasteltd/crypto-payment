## 2. 登录调用链

```text
微信小程序
  -> Taro.login()
  -> 获得一次性 code
  -> POST /v1/auth/wechat-mini-program
  -> API Server 调用微信 /sns/jscode2session
  -> 获得 openid / unionid / session_key
  -> 仅保存身份标识，丢弃 session_key
  -> 创建或读取灵办词元用户与个人工作区
  -> 返回 accessToken / refreshToken / currentWorkspace
  -> 小程序进入已登录状态
```

登录请求：

```json
{
  "code": "wx.login 返回的临时凭证"
}
```

接口响应沿用统一 `AuthSessionResponse`，移动端继续使用既有令牌刷新、工作区切换与退出登录逻辑。

## 3. 前端配置

### 3.1 微信 AppID

`app/mobile/project.config.json` 已配置正式小程序信息：

```json
{
  "projectname": "灵办",
  "appid": "wx4b21e9b9200dcf9b"
}
```

源码工程、`dist/project.config.json` 与后端身份域必须保持同一 AppID。

当前工程使用 Taro 微信小程序构建，入口由 `app.json`、WXML 与 WXSS 组成。AppID 必须由微信开发者工具识别为微信小程序类型。

### 3.2 API 基址

小程序构建前必须提供可公网访问的 HTTPS API 基址：

```powershell
$env:TARO_APP_API_BASE_URL = "https://codex-miniapp.sidcloud.cn"
pnpm -C app/mobile build:weapp
```

| 配置 | 约束 |
|---|---|
| 协议 | 正式环境使用 HTTPS |
| 地址 | 浏览器或小程序设备能够访问，禁止使用 `127.0.0.1` 和 `localhost` |
| 微信后台 | 将 API 域名加入小程序服务器域名的 `request` 合法域名 |
| CORS | H5 继续按实际 Web 域名配置；小程序请求不依赖浏览器 CORS |
| 证书 | 使用受信任且未过期的公网证书 |

仓库默认将微信小程序请求基址设为 `https://codex-miniapp.sidcloud.cn`，构建环境可通过 `TARO_APP_API_BASE_URL` 覆盖。微信公众平台需要登记 `https://codex-miniapp.sidcloud.cn` 为 `request` 合法域名。

```text
GET https://codex-miniapp.sidcloud.cn/health -> 200
POST https://codex-miniapp.sidcloud.cn/v1/auth/wechat-mini-program -> 无效 code 返回 401 / AUTH_WECHAT_CODE_INVALID / 40029
```

健康检查证明公网反代可达。登录路由、服务端凭证、微信上游错误映射和开发者工具真实 `wx.login` code 换取灵办会话均已通过。

## 4. 后端配置

后端运行环境需要设置：

```dotenv
LINGBAN_WECHAT_MINI_PROGRAM_APP_ID=wx4b21e9b9200dcf9b
LINGBAN_WECHAT_MINI_PROGRAM_APP_SECRET=<由服务端密钥配置注入>
LINGBAN_WECHAT_MINI_PROGRAM_API_BASE_URL=https://api.weixin.qq.com
LINGBAN_WECHAT_MINI_PROGRAM_REQUEST_TIMEOUT_MS=5000
```

| 变量 | 必填 | 作用 | 安全要求 |
|---|---|---|---|
| `LINGBAN_WECHAT_MINI_PROGRAM_APP_ID` | 是 | 标识微信小程序 | 必须与构建使用的 AppID 一致 |
| `LINGBAN_WECHAT_MINI_PROGRAM_APP_SECRET` | 是 | 服务端调用微信登录接口 | 仅注入 API 服务，禁止进入前端构建物、日志和 Git |
| `LINGBAN_WECHAT_MINI_PROGRAM_API_BASE_URL` | 否 | 微信 API 地址 | 正式环境保持官方地址 |
| `LINGBAN_WECHAT_MINI_PROGRAM_REQUEST_TIMEOUT_MS` | 否 | 上游请求超时 | 默认 5000 毫秒 |

PostgreSQL 部署需要在发布前执行数据库迁移：

```powershell
pnpm -C app/api build:local
pnpm -C app/api migrate
```

新增表：`lingban_auth_external_identities`。

## 6. 身份与账户规则

| 场景 | 行为 |
|---|---|
| 用户首次微信登录 | 创建内部用户、个人工作区与 owner 成员关系 |
| 同一 AppID、同一 openid 再次登录 | 返回既有用户和工作区 |
| 不同小程序 AppID | 按独立身份域处理 |
| 微信返回 unionid | 保存为跨应用身份关联依据 |
| 用户或工作区被停用 | 拒绝登录或拒绝进入停用工作区 |
| 微信 code 无效或过期 | 返回 `AUTH_WECHAT_CODE_INVALID` |
| 后端缺少 AppID 或 AppSecret | 返回 `AUTH_WECHAT_NOT_CONFIGURED` |

当前版本保持微信账户与邮箱账户独立。后续若需要账户合并，应增加已登录态绑定流程、二次身份校验、冲突处理和解绑审计，禁止根据昵称或未验证邮箱自动合并。

## 7. 安全约束

1. AppSecret 仅存在于后端密钥管理系统或运行时环境变量。
2. 小程序 `code` 作为一次性短期凭证使用，后端收到后立即向微信换取身份。
3. `session_key` 不写入数据库、文件存储、响应体或业务日志。
4. 身份主键使用 `provider + app_id + provider_subject`，避免不同小程序 openid 冲突。
5. 登录成功后统一签发灵办词元 access token 和 refresh token。
6. 生产环境需要为登录接口配置限流、异常登录监控和审计告警。

## 10. Taro Vite 运行时检查

### 10.1 `ENABLE_COOKIE is not defined`

Taro 4.2 的 `@tarojs/plugin-http` 通过 Webpack 钩子注入 `ENABLE_COOKIE`。本工程使用 Vite Runner，需要在 `config/index.ts` 的 `defineConstants` 中显式设置：

```ts
defineConstants: {
  ENABLE_COOKIE: "false",
}
```

未注入时，微信开发者工具会在 `taro.js` 启动阶段重复输出：

```text
ReferenceError: ENABLE_COOKIE is not defined
MiniProgramError
SystemError (appServiceSDKScriptError)
```

这些日志属于同一启动异常的重复上报。

### 10.2 构建门禁

`pnpm -C app/mobile build:weapp` 在 Taro 构建后自动执行 `scripts/verify-weapp-build.mjs`，检查：

1. `app.js / app.json / app.wxss / taro.js / project.config.json` 完整存在。
2. 全部 JavaScript 产物不存在未替换的 `ENABLE_*` 运行时常量。
3. 产物包含微信 AppService 所需的 Zod `jitless` 运行时配置。
4. 源码工程与 `dist` 的微信 AppID 一致。
5. `app.json` 与 `project.config.json` 均为合法 JSON。

### 10.3 `TypeError: c is not a function`

Zod 4 默认使用动态函数生成对象 Schema 解析器。微信 AppService 禁止执行该类 JIT 代码，Schema 首次解析时会重复上报：

```text
TypeError: c is not a function
MiniProgramError
SystemError (appServiceSDKScriptError)
```

契约包统一通过 `packages/contracts/src/zod.ts` 导出 Zod，并在 `TARO_PLATFORM=mini` 时启用：

```ts
z.config({ jitless: true });
```

该配置必须先于全部 Schema 构造执行。契约源码禁止直接从 `zod` 导入 `z`，新增 Schema 需要继续从 `./zod.js` 导入。
