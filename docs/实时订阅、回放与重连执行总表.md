## 2. 当前实时事实矩阵

| 证据 | 当前实现 | 当前含义 | 当前缺口 |
|---|---|---|---|
| `registerRealtimeSocketRoutes()` | 建连即发 snapshot、backlog、ack | WS 主链路可直接消费完整 run | 无认证、无重连水位线 |
| `GET /v1/runs/:runId/stream` | SSE 同步首帧 snapshot 和 backlog | 浏览器 fallback 已具基础能力 | 无 `Last-Event-ID` |
| `InMemoryRunEventBus` | 内存持有 + `.jsonl` 落盘 | backlog 与重启后回放已有基础 | 无分页、无 cursor |
| `createRunsRealtimeClient()` | SDK 暴露 `connect/sendMessage/approve/cancel` | 双端已共用同一套 WS client | 无 SSE 统一 client |
| `ApiConnector` internal 回调 | bridge 可回传 `register / status / events / artifacts`，并带 internal token | runtime 事件与状态可以进入 API 并广播 | 缺 trace id、幂等键与更细粒度退避策略 |

## 3. 实时通道分层执行矩阵

| 层级 | 当前通道 | 当前责任模块 | 当前作用 |
|---|---|---|---|
| L1 | WebSocket | `socket-routes.ts` | 主订阅、主交互通道 |
| L2 | SSE | `runs/routes.ts` | WebSocket 不可用时的回退 |
| L3 | HTTP 动作 | `POST /messages`、`/approvals`、`/cancel` | 非实时动作补偿通道 |
| L4 | Internal ingest | `/internal/runs/:runId/events` | bridge 到 API 的事件回流 |
| L5 | Event Bus | `InMemoryRunEventBus` | API 内广播与 backlog |
| L6 | Snapshot 投影 | `applyBridgeEventToRunSnapshot()` | 前端本地状态增量更新 |

## 4. WS 建连执行矩阵

| 步骤 | 执行方 | 当前动作 | 输出 |
|---|---|---|---|

## 6. SSE 建连执行矩阵

| 步骤 | 执行方 | 当前动作 | 输出 |

## 7. bridge 事件进入实时面的执行矩阵

| 步骤 | 执行方 | 当前动作 | 输出 |
|---|---|---|---|
| 1 | bridge | 生成 `BridgeEvent[]` | runtime 事件数组 |
| 2 | `ApiConnector` | `POST /internal/bridges/register`、`/status`、`/events`、`/artifacts` | API internal 回调请求 |
| 3 | API | schema parse + internal token 校验 | 校验来源与 payload |

| 7 | WS/SSE | 订阅 listener 收到 envelope | 前端实时更新 |

## 8. backlog 写入与回放执行矩阵

| 动作 | 当前方法 | 当前行为 | 当前风险 |
|---|---|---|---|
| 写入单事件 | `append()` | 先 parse，再生成 `eventId`，写内存，再 append `.jsonl` | 无批事务 |
| 写入批事件 | `appendMany()` | 顺序循环调用 `append()` | 中间失败可能半写入 |
| 启动恢复 | `#loadFromDisk()` | 扫描所有 `.jsonl` 重建内存 | 大规模时启动成本高 |
| 首次订阅回放 | `sendBacklog()` / SSE for-loop | 全量按记录顺序推送 | 无分页 |
| 增量广播 | `subscribe()` listener | 逐条 envelope 推送 | 无 backpressure |

## 9. 当前 ack 语义矩阵

| 场景 | 当前 ack 时机 | 当前语义 |
|---|---|---|
| WS 首次建连成功 | snapshot + backlog 之后 | 服务端确认通道可用 |
| `runs.subscribe` | snapshot 之后 | 重订阅成功 |
| `runs.sendMessage` | `runsService.sendMessage()` 返回后 | API 已接收并写入聚合 |
| `runs.approve` | `runsService.approve()` 返回后 | API 已接收并写入审批结果 |
| `runs.cancel` | `runsService.cancel()` 返回后 | API 已接收终止请求 |
| SSE | 当前无 ack 概念 | 依赖连接本身与 frame 收到 |

## 10. 当前错误出口矩阵

| 场景 | 当前错误出口 | 当前行为 |
|---|---|---|
| WS path 参数非法 | `runs.error` + `socket.close(1008)` | 关闭连接 |
| run 不存在 | `runs.error` + `socket.close(1008)` | 关闭连接 |
| 消息 JSON 无法解析 | `runs.error` | 保持连接 |
| 消息体 schema 不合法 | `runs.error` | 保持连接 |
| payload.runId 与 URL 不一致 | `runs.error` | 保持连接 |
| SSE 路径/文件错误 | HTTP 错误响应 | 连接建立失败 |
| internal ingest 异常 | HTTP error + connector throw | bridge 侧收到失败 |

## 12. 重连与恢复目标执行矩阵

| 能力 | 当前状态 | 正式要求 |
|---|---|---|
| WS 自动重连 | 缺失 | SDK 内建指数退避与抖动 |

## 15. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无认证 | 任意知道 runId 的客户端理论上可订阅 | 不能生产化 | P0 |
| 无重连水位线 | 断连后只能全量重放 | 大实例成本高 | P0 |
| SSE 无统一 SDK | 双端各自维护 fallback | 行为不一致 | P1 |
| internal ingest 缺正式鉴权与重试 | bridge 到 API 链路稳定性和安全性不足 | P1 |

## 18. 回放/重连收口顺序表

| 阶段 | 动作 | 收口结果 |
|---|---|---|
| Phase 1 | 补 `event_seq/cursor/Last-Event-ID` | 断点恢复成立 |
| Phase 2 | 统一 SDK 的 WS/SSE reconnect/backoff | 双端行为收敛 |
| Phase 3 | 为 event bus 引入共享 event store | 多实例回放成立 |
| Phase 4 | 为 internal ingest 补鉴权与重试 | bridge 回流更稳 |
