## 4. 测试分层执行矩阵

| 层级 | 目标对象 | 建议工具 | 最低覆盖重点 |
|---|---|---|---|
| 单元测试 | `packages/contracts`、`packages/domain-models`、`packages/api-sdk`、selector/adapter 函数 | `vitest` | schema parse、状态迁移、event 投影、URL 构造、权限 selector |
| 模块集成测试 | `app/api`、`app/run-worker`、`app/container-bridge` | `vitest` + Node 原生 `fetch`/临时目录 | route -> service -> repository、runtime 物料生成、secret/mcp 物化 |
| 页面集成测试 | `app/dashboard`、`app/mobile` H5 | `vitest` + `@testing-library/react` | 路由装载、store 初始化、query fallback、消息发送按钮状态 |
| 浏览器 E2E | Dashboard、H5 | `@playwright/test` | 登录、工坊启动 run、任务对话、文件下载、工作区切换 |
| 运行闭环回归 | API + Worker + Bridge + runner image | `playwright` + docker compose / 本地 harness | 创建 run -> 启动 bridge -> 发消息 -> 文件回流 -> 结束态 |
| 发布前人工验收 | 全链 | 手工脚本 + 截图/日志归档 | 核验复杂第三方 MCP、弱网、长会话、审批流 |

## 6. 单元测试夹具矩阵

| 目标模块 | 核心用例 | 夹具要求 |
|---|---|---|
| `packages/contracts` | schema 正常解析、字段缺失、枚举非法、兼容字段演进 | 维护 `valid/*.json` 与 `invalid/*.json` |

## 12. 失败处理执行矩阵

| 失败类型 | 当前状态 | 建议动作 |
|---|---|---|
| 构建失败 | 目前人工查看终端 | 统一输出到 CI artifact 并标注仓库/模块 |

## 13. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无正式 `test` 脚本体系 | 基本只有 build/typecheck | 回归成本高 | P0 |
| 无 API/Worker/Bridge 集成测试 | 运行主链缺自动化验证 | 改动风险高 | P0 |
| 无前端页面测试 | H5/Dashboard 主要靠人工点验 | UI 回归难控 | P1 |
| 无证据归档目录约定 | 构建和人工验收证据易散落 | 里程碑审查困难 | P1 |
