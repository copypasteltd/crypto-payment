## 4. Dashboard `InstancesPage` 装载顺序矩阵

| 顺序 | 当前执行 | 作用 |
|---|---|---|
| 1 | 读取 `useParams()` | 获取 `instanceId/detailTab` |
| 2 | 读取 `dashboardUiStore` | 获取当前 workspace、activeInstance、draft、tab |
| 3 | 读取本地静态 `instances/dashboardServices/dashboardWorkspaces` | 形成原型数据基线 |
| 4 | 组合 live runs 与静态实例 | 形成 `mergedInstances` |
| 5 | 按 workspace、live、更新时间排序 | 得到 `sortedInstances` |
| 6 | 校验当前 `instanceId` 是否属于当前 workspace | 必要时 `navigate` 到 fallback 实例 |
| 7 | 校验 `detailTab` 合法性 | 不合法回退 `overview` |
| 8 | 决定 `liveMode` | `run_*` 才启实时链 |
| 9 | 建立 `useDashboardRunStream()` | 更新 Query Cache |
| 10 | 页面内根据 tab 加载预览 query 或发送 mutation | 文件预览、消息发送 |

## 6. Dashboard 导航回退执行矩阵

| 场景 | 当前行为 | 代码依据 |
|---|---|---|
| URL 中实例不属于当前 workspace | 导航到当前 workspace 第一个实例 | `useEffect + navigate()` |

## 9. Mobile `services/detail` 装载顺序矩阵

| 顺序 | 当前执行 | 作用 |
|---|---|---|
| 1 | 读取 `router.params.id` | 获取服务 id |
| 2 | 读取 `currentWorkspaceId` store | 获取当前空间 |
| 3 | `findVisibleService(id, currentWorkspace.id)` | 依据 workspace 可见性取服务 |
| 4 | 若 `id` 与可见服务不一致则 `redirectTo` | 修正越界或错误 id |
| 5 | 点击启动时 `buildMobileRunInput(service.id, workspaceId)` | 生成 `CreateRunInput` |
| 6 | 调用 `mobileRunsApi.createRun()` | 创建实例 |
| 7 | 成功后 `navigateTo(/pages/tasks/detail?id=runId)` | 进入 live 任务详情 |
| 8 | 失败时 `showToast("创建实例失败")` | 轻量错误提示 |

## 10. Mobile `tasks/detail` 装载顺序矩阵

| 顺序 | 当前执行 | 作用 |
|---|---|---|
| 1 | 读取 `router.params.id` | 获取任务或 run id |
| 2 | `isLiveTaskId(id)` | 判断是否 live run |
| 3 | 读取 `currentWorkspaceId/taskDrafts` store | 获取空间与草稿 |
| 4 | live 场景执行 `getRun()` query | 拉取权威快照 |
| 5 | `mapRunSnapshotToMobileTask()` | 转换为页面模型 |
| 6 | 若 live task workspace 与当前空间不一致则回退本地可见任务 | 防止跨空间展示 |
| 7 | 若当前 id 不可见则 `redirectTo` 替代任务 | 修正入口 |
| 8 | `useMobileRunStream()` 建立实时链 | 持续更新 Query Cache |
| 9 | 发送消息时先走 realtime，失败再走 HTTP mutation | 保持对话连续性 |

## 11. Mobile 路由回退执行矩阵

| 场景 | 当前行为 | 代码依据 |
|---|---|---|
| 服务不在当前 workspace 可见范围 | 重定向到 fallback 服务或显示空态 | `findVisibleService()` + `redirectTo` |
| 任务不在当前 workspace 可见范围 | 重定向到 fallback 任务或显示空态 | `findVisibleTask()` + `redirectTo` |
| live run 正在加载 | 展示 loading hero | `liveTaskQuery.isPending` |
| 当前空间无任何任务 | 展示空态并引导回工坊 | `!task` |
| 任务页跳文件页 | `navigateTo(/pages/tasks/files?id=task.id)` | 维持同 run 上下文 |

## 15. 正式守卫执行矩阵

| 守卫层 | 进入时机 | 正式动作 |
|---|---|---|
| App 初始化守卫 | 首次进入应用 | 拉当前用户与当前 workspace |
| 路由前守卫 | 进入 `Creator`/`Governance` 等敏感区前 | 校验 role，不通过则 403 页 |
| 资源守卫 | 进入具体 `run`/`service` 页面前 | 校验资源是否属于当前 workspace 与 scope |
| 文件守卫 | 打开预览/下载前 | 请求文件 grant 或预览权限 |
| 实时守卫 | 建立 WS/SSE 前 | 校验 session token 与 run scope |

## 16. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 路由守卫全部缺失 | Creator / Governance 无权限门槛 | 正式接入风险高 | P0 |
| 工坊与 Creator 仍依赖静态数据 | 路由进入后无真实装载链 | 无法联调正式 API | P0 |
| 页面错误分类不足 | query 失败大量回退 `null` | 空态与异常态混淆 | P1 |
| store 持久化与 URL 状态未完全对齐 | 刷新后部分状态丢失 | 使用连续性不足 | P1 |

## 19. 路由收口顺序表

| 阶段 | 动作 | 收口结果 |
|---|---|---|
| Phase 1 | 补 `auth/me` 与 `workspaces` bootstrap | 所有路由进入前有权威上下文 |
| Phase 2 | 为 Creator、Governance、Run 详情补资源守卫 | 越权页面不能直接渲染 |

| Phase 4 | 为文件预览/下载补授权态与错误页 | 文件页进入规则可控 |
