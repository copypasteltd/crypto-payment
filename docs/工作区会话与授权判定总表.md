| 角色 | 作用域 | 核心职责 |
|---|---|---|

| `workspace_admin` | 工作区 | 管理运行配置、审计查看、部分治理 |

## 9. 关键授权判定链路总表

| 场景 | 必做判定 |
|---|---|
| 创建 run | 当前用户是否属于 `workspaceId`；是否有目标服务执行权；是否可使用相关 sessionVersion；是否可绑定相关凭证与 MCP |
| 查看 run | 当前用户是否可见该 run 所属工作区；是否满足 run 级别访问策略 |
| 发送消息 | 当前用户是否可操作该 run；run 是否未终态 |
| 审批 | 当前用户是否具备 `approver` 或等效权限；审批对象是否属于其工作区或治理范围 |
| 文件下载 | 当前用户是否可读 run；路径是否属于该 run；文件是否允许下载 |
| Creator 发布 | 当前用户是否具备 `creator_maintainer`；package 是否属于当前工作区；gate 是否已通过 |
| 审计导出 | 当前用户是否具备导出权限；导出 profile 是否允许；范围是否属于当前工作区或治理范围 |

## 16. 当前缺口与补齐顺序表

| 优先级 | 缺口 | 影响 | 补齐动作 |
|---|---|---|---|
| P0 | 无正式登录与会话 | 无法开放真实用户 | 建 `auth_session` 与 `/auth/*` |
| P0 | 无工作区成员判定 | 多租户边界缺失 | 建 `workspace_member` 与 ACL evaluator |
| P0 | 前后端资源路由无守卫 | 资源可见性不可控 | 在 API 与前端引入 guard |
| P1 | internal bridge 仅具基础 token 鉴权 | 服务间链路仍缺轮换、trace 与更强身份机制 | 引入 token 轮换或 mTLS |
| P1 | 偏好仅本地存储 | 跨端体验不一致 | 建 `workspace_preference` |
