## 5. Bridge CLI 配置优先级矩阵

| 配置项 | 当前读取逻辑 | 实际优先级 | 当前结果 |
|---|---|---|---|
| `contextPath` | `process.env.BRIDGE_CONTEXT_PATH ?? process.argv[2]` | 环境变量 > CLI 参数 | 以 env 为准 |
| `runtimeHints` | 仅当 `RUNTIME_CONFIG_PATH` 存在时读取 | env 指定文件 > 无 hints | 可补充 runtimeDir/outputsPath 推导 |
| `runtimeDir` | `process.env.RUNTIME_DIR ?? runtimeHints.workspace.containerPaths.runtimePath ?? path.dirname(contextPath)` | 环境变量 > runtime JSON > context 相邻目录 | 已形成三级回退 |
| `outputsPath` | `process.env.OUTPUTS_PATH ?? runtimeHints.workspace.containerPaths.outputsPath ?? dirname(targetPath)/outputs` | 环境变量 > runtime JSON > 目标路径同级默认 | 已形成三级回退 |
| `CODEX_BIN` | CLI 读取 env 后传给 `buildContainerBridge()` | env > builder 默认 | 当前由 env 驱动 |
| `CODEX_ARGS_JSON` | `process.env.CODEX_ARGS_JSON ? JSON.parse(...) : undefined` | env > 无参数 | 当前仅 env 驱动 |

## 6. `buildContainerBridge()` 内部配置优先级矩阵

| 配置项 | 当前逻辑 | 实际优先级 |
|---|---|---|
| `context` | `options.context` 存在则直接使用，否则从 `RUN_ID/WORKSPACE_ID/TARGET_PATH/INITIAL_PROMPT` 构造 | 显式 `options.context` > env fallback |
| `workspaceRoot` | `options.workspaceRoot ?? path.dirname(context.targetPath)` | 显式参数 > targetPath 派生 |
| `runtimeDir` | `options.runtimeDir ?? path.join(workspaceRoot, "runtime")` | 显式参数 > 派生默认 |
| `outputsPath` | `options.outputsPath ?? path.join(workspaceRoot, "outputs")` | 显式参数 > 派生默认 |
| Codex command | `options.codex.command ?? process.env.CODEX_BIN ?? "codex"` | 显式参数 > env > `"codex"` |
| Codex args | `options.codex.args ?? []` | 显式参数 > 空数组 |
| Codex cwd | `options.codex.cwd ?? context.targetPath` | 显式参数 > targetPath |
| Codex env | `RUN_ID/WORKSPACE_ID/TARGET_PATH` + `options.codex.env` | 基础上下文 env + 额外 env 合并 |

## 7. Secret 注入优先级矩阵

| 场景 | 当前逻辑 | 优先级 | 当前风险点 |
|---|---|---|---|
| env 类型 secret | `secretValues[credentialId]` 存在则写入 `env[mount.envName]` | 显式 `secretValues` > 继承 `process.env[mount.envName]` | 缺来源审计 |
| env 类型 secret 缺失 | 回退读取当前进程 `process.env` | 继承环境变量 | 开发环境误继承风险 |
| file 类型 secret | `secretValues[credentialId]` 存在则写文件 | 显式 `secretValues` > 现有文件路径 | 缺轮换链路 |
| file 类型 secret 缺失 | 仅 `fs.access(filePath)` 校验现有文件存在 | 现有宿主文件 | 无 provider broker |

## 11. 敏感项边界矩阵

| 配置项 | 当前归类 | 应否进入 Git | 正式建议载体 |

## 13. 正式系统建议的配置治理矩阵

| 领域 | 正式建议 | 当前状态 |
|---|---|---|
| 配置 schema 校验 | 独立 `config` 包 + zod schema | 已具备 API / Worker / Bridge 基础 schema，前端公开配置与统一 fail-fast 仍需扩展 |

| 秘钥来源审计 | 记录 provider、mount、rotation | 缺失 |
| 生效快照 | 每个 run 固化 config snapshot | 仅 runtime 文件具备局部基础 |
| 环境分层 | dev/staging/prod/worker/runtime 分层 | 仅局部约定 |
| 配置变更审计 | 发布或部署变更进入 audit | 缺失 |

## 14. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无统一配置 schema | 各文件零散读 env | 配置错误难在启动前暴露 | P0 |
| 密钥治理尚未正式化 | secret 只支持 env/file 基础落盘 | 第三方凭证无法审计与轮换 | P0 |
| bridge 回调观测与幂等不足 | register/status/events/artifacts 已闭环，但 trace 与重复投递治理不足 | 调试链与生产链故障定位成本偏高 | P1 |
| 分环境 `.env` overlay 缺失 | 团队协作仍需手工维护 dev/staging/prod 差异 | 新环境启动和部署对齐成本偏高 | P1 |
