## 4. 当前卡片类型矩阵表

| 卡片类型 | 当前来源 | 当前状态字段 | 当前动作 | 当前消费面 |
|---|---|---|---|---|
| `approval` | `snapshot.approvals.filter(state=pending)` | `待确认` | `继续执行`、`先解释原因` | Mobile 任务对话 |
| `file` | 有文件可见且非失败/非完成主结果 | 继承任务状态标签 | `查看文件`、`继续追问` | Mobile 任务对话 |
| `result` | `snapshot.run.status === SUCCEEDED` 且有文件 | `已完成` | `查看文件`、`继续追问` | Mobile 任务对话 |
| `error` | `snapshot.run.status === FAILED` | `错误处理` | `解释失败原因`、`继续重试` | Mobile 任务对话 |
| `attachment` | 未实现 | 无 | 无 | 无 |

## 5. 事件到卡片的当前映射表

| 事件/状态 | 当前事件源 | 当前投影 | 当前问题 |
|---|---|---|---|
| `approval.requested` | bridge event | `approval` 卡片 | 缺审批已处理结果卡片 |
| `files.synced` / `file.changed` | bridge event | `file` 或 `result` 卡片 | 文件变化没有最小差量展示 |
| `run.failed` | bridge event / run status | `error` 卡片 | 错误范围与恢复动作粒度不足 |
| `conversation.message` | bridge event | 普通消息 | 不能承载结构化动作语义 |
| `artifact.ready` | bridge event | 当前未独立卡片化 | 结果卡片主要依赖 run status + files 推断 |

## 9. 正式消息对象表

### 9.1 会话项对象表

| 对象 | 主键 | 核心字段 | 说明 |
|---|---|---|---|
| `conversation_item` | `item_id` | `run_id`、`message_id`、`item_type`、`role`、`created_at`、`status` | 统一普通消息与结构化卡片的会话流对象 |
| `conversation_card` | `item_id` | `card_type`、`title`、`summary`、`status_label`、`severity`、`payload` | 审批/附件/文件/结果/错误等卡片载体 |
| `conversation_action` | `action_id` | `item_id`、`action_type`、`label`、`mode`、`draft_template`、`target_ref` | 卡片动作定义 |

### 9.2 卡片类型表

| `card_type` | 用途 | 典型来源 |
|---|---|---|
| `approval.card` | 审批确认与影响说明 | `approval.requested` |
| `attachment.card` | 上传材料、共享文件引用 | `attachment.uploaded`、`workspace.file.referenced` |
| `file.card` | 中间文件、日志、截图可查看 | `files.synced`、`file.changed` |
| `result.card` | 最终结果包、交付物 | `artifact.ready`、`run.succeeded` |
| `error.card` | 错误、阻塞、恢复建议 | `run.failed`、policy block |
| `notice.card` | 非阻断提示、系统说明 | 系统规则提示、治理提醒 |

## 10. 正式动作模式矩阵表

| `action_type` | `mode` | 说明 | 示例 |
|---|---|---|---|
| `approve` | `direct` | 直接调审批接口 | 确认提交报税 |
| `reject` | `direct` | 直接驳回审批 | 拒绝高风险出网 |
| `open_file` | `route` | 深链到文件页或具体文件 | 查看 `filing-slip.pdf` |
| `send_template_message` | `draft` | 把模板写入输入区 | 请先解释当前错误原因 |
| `retry_step` | `direct_or_draft` | 直接重试或先写草稿确认 | 继续重试上一阶段 |
| `open_detail_sheet` | `sheet` | 打开审批详情/影响范围 | 查看审批影响范围 |

## 11. 文件 / 结果卡片正式执行表

| 阶段 | 输入 | 正式动作 | 输出 |
|---|---|---|---|
| 1 | `files.synced` / `artifact.ready` | 生成 `file.card` 或 `result.card` | 会话流新增卡片 |
| 2 | 卡片创建 | 绑定 `open_file`、`download_bundle`、`send_template_message` 动作 | 卡片动作可执行 |
| 3 | 用户点击查看文件 | 深链到文件页，并带 `path/fileId/messageId` | 精确定位对应文件 |
| 4 | 用户点击继续追问 | 写入引用回复模板或直接发送上下文问题 | 同一任务继续推进 |

## 12. 审批 / 错误卡片正式执行表

| 阶段 | 输入 | 正式动作 | 输出 |
|---|---|---|---|
| 1 | `approval.requested` / `run.failed` | 生成 `approval.card` / `error.card` | 会话流新增卡片 |
| 2 | 卡片创建 | 绑定 `approve/reject/open_detail_sheet/send_template_message/retry_step` | 用户可直接处理 |
| 3 | 用户点击确认/驳回 | 调正式审批接口，卡片进入处理中态 | 防重复点击 |
| 4 | 服务端确认 | 回写 `approval.resolved` 或 `run.status.changed` | 卡片状态更新，消息流补一条结果消息 |
| 5 | 列表/通知联动 | 任务列表、通知中心同步变更 | 外溢提醒完成 |

## 16. 验收判定表

| 验收项 | 判定标准 |
|---|---|
| 审批卡片可直接处理 | 用户能在消息流内完成审批，结果即时回写 |
| 文件卡片可精准定位 | 从通知或消息卡片能直接打开对应文件 |
| Dashboard / Mobile 对齐 | 同一 run 在双端看到同源的卡片类型与动作 |
| 错误恢复可操作 | 错误卡片能给出可执行恢复路径 |
| 结果回流清晰 | 结果卡片出现后，任务列表、通知中心、文件页同步刷新 |
