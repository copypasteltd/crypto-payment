## 2. Run 状态流转矩阵表

| 当前状态 | 允许流转到 | 说明 |
|---|---|---|
| `CREATED` | `READY`、`FAILED`、`CANCELLED` | run 创建后等待预处理 |
| `READY` | `QUEUED`、`FAILED`、`CANCELLED` | 运行物料准备完毕 |
| `QUEUED` | `STARTING`、`FAILED`、`CANCELLED` | 等待启动执行单元 |
| `STARTING` | `RUNNING`、`FAILED`、`CANCELLED` | 容器或 bridge 启动中 |
| `RUNNING` | `WAITING_APPROVAL`、`SUCCEEDED`、`FAILED`、`CANCELLED` | 正常执行态 |
| `WAITING_APPROVAL` | `RUNNING`、`FAILED`、`CANCELLED` | 等待用户审批 |
| `SUCCEEDED` | 无 | 终态 |
| `FAILED` | 无 | 终态 |
| `CANCELLED` | 无 | 终态 |

## 7. Bridge 事件协议总表

| 事件类型 | 主要字段 | 当前生产方 | 当前消费方 | 对 run 快照的影响 |
|---|---|---|---|---|
| `run.status.changed` | `runId`、`status`、`occurredAt`、`reason?` | bridge / worker | API service / event bus / 前端 | 更新 `run.status` 与 `statusReason` |
| `conversation.message` | `message` | bridge | API service / 前端 | 追加消息，按 `messageId` 去重 |
| `approval.requested` | `approval` | bridge | API service / 前端 | upsert 审批记录 |
| `artifact.ready` | `artifact` | bridge | API service / 前端 | upsert 产物记录 |
| `files.synced` | `runId`、`files[]`、`occurredAt` | bridge | API service / 前端 | 全量替换 `files` |
| `file.changed` | `runId`、`file`、`occurredAt` | bridge / watcher | API service / 前端 | 按 `path` upsert 单文件 |
| `heartbeat` | `runId`、`occurredAt` | bridge | API service / 运维 | 当前不修改快照 |
| `run.failed` | `runId`、`occurredAt`、`error` | bridge / runtime | API service / 前端 | 将 run 投影为 `FAILED` |

## 14. 事件到快照投影规则表

| 事件类型 | 投影策略 | 去重/覆盖规则 |
|---|---|---|
| `run.status.changed` | 调用 `projectRunStatus` 更新状态 | 同状态允许更新原因与时间 |
| `conversation.message` | 追加到 `messages` | 按 `messageId` 去重 |
| `approval.requested` | 写入 `approvals` | 按 `approvalId` upsert |
| `artifact.ready` | 写入 `artifacts` | 按 `artifactId` upsert |
| `files.synced` | 覆盖 `files` | 全量替换 |
| `file.changed` | 更新 `files` | 按 `path` upsert |
| `run.failed` | 强制转成 `FAILED` | 使用 `error` 填充 `statusReason` |
| `heartbeat` | 不修改快照 | 仅保活用途 |

## 16. Bridge Registry 命令分发表

| 场景 | 当前行为 |
|---|---|
| bridge 已注册且 controller 已附着 | 立即串行分发 |
| bridge 已注册但 controller 未附着 | 放入 `pendingCommands` |
| controller 后续附着 | 依次冲刷待发命令 |
| controller 分发报错 | 错误被当前 promise 链吞并后继续后续命令 |
| bridge 注销 | 清理连接、控制器、待发命令与 dispatch chain |

## 17. Heartbeat 与终态控制表

| 项目 | 当前行为 | 影响 |
|---|---|---|
| `heartbeat` 事件 | 写入 event bus | 前端可感知运行活性，当前不改快照 |
| 终态集合 | `SUCCEEDED`、`FAILED`、`CANCELLED` | bridge CLI 与 orchestrator 用于结束判断 |
| `run.failed` | 映射为 `FAILED` | 强制终止到失败终态 |

## 18. 当前协议空缺表

| 协议域 | 当前缺口 |
|---|---|
| Realtime 鉴权 | WebSocket / SSE 未接正式认证与工作区权限 |
| 事件签名 | 内部 bridge 事件无签名校验 |
| 事件重放 | 无 offset、cursor、watermark 协议 |
| 心跳治理 | 无超时踢除与失联状态策略 |
| 跨节点广播 | 无 Redis pub/sub 或事件中间件 |
| 审批审计 | 审批消息无正式审计协议扩展 |

## 20. 当前非生产级实时缺口表

| 能力 | 当前缺口 | 影响 |
|---|---|---|
| 鉴权 | WS / SSE 无正式认证 | 无法开放真实多用户 |
| 恢复 | 无 `lastEventId`、cursor、resume token | 断线恢复能力弱 |
| 广播 | 无跨实例事件中间件 | API 不能横向扩展 |
| 心跳治理 | 无超时踢除与自动失联判定 | 长会话稳态能力不足 |
| 审计 | 审批、控制动作缺正式审计扩展 | 治理追溯不足 |
| 签名 | `/internal` 回流无签名校验 | bridge 内部通道不具备生产级安全性 |

## 21. 实时协议收口顺序表

| 顺位 | 收口项 | 目标结果 |
|---|---|---|
| 1 | WS / SSE 鉴权 | 订阅链具备身份与工作区作用域 |
| 2 | 结构化错误与 ack 强化 | 前端能区分订阅失败、权限失败、消息失败 |
| 3 | resume / backlog 协议 | 断连重连具备可恢复能力 |
| 4 | Redis pub/sub 或事件中间件 | API 具备横向扩展前提 |
| 5 | 内部事件签名与审计 | bridge 回流进入生产级安全口径 |
