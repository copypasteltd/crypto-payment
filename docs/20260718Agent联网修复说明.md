# Agent 联网修复说明

## 1. 修复目标

所有新建 Agent Run 默认具备公网访问能力，可通过 Shell、npm、pip、Git、Playwright 和第三方 MCP 访问外部服务。Target Path 文件权限、Run 级凭证隔离和 Provider 绑定继续生效。

## 2. 联网控制链

| 层级 | 生产默认值 | 作用 | 生效位置 |
|---|---|---|---|
| Docker Network | `lingban-egress-default`，`Internal=false` | 为 Run 容器提供 DNS、网关和公网路由 | Docker Host |
| Runtime egress proxy | `LINGBAN_RUNTIME_EGRESS_PROXY_ENABLED=false` | 关闭平台代理白名单转发 | Run Worker |
| Runtime egress firewall | `LINGBAN_RUNTIME_EGRESS_FIREWALL_ENABLED=false` | 取消容器内默认拒绝的 iptables 规则 | Run Worker / Runner entrypoint |
| Codex 全局沙箱 | `sandbox_mode = "workspace-write"` | 将文件写入限制在工作区 | Run 独立 `CODEX_HOME/config.toml` |
| Codex 全局网络 | `sandbox_workspace_write.network_access=true` | 允许 workspace-write 沙箱出站 | Run 独立 `CODEX_HOME/config.toml` |
| Codex Turn 网络 | `sandboxPolicy.networkAccess=true` | 为每个新 Turn 显式启用网络 | Container Bridge `turn/start` |

联网能力需要上述层级同时满足。审批模式只处理动作确认，不改变网络策略。

## 3. Codex App Server 协议约束

HZ01 当前使用 `codex-cli 0.144.1`。该版本字段格式如下：

| 请求 | 字段 | 固定值 |
|---|---|---|
| `thread/start` | `sandbox` | `workspace-write` |
| `turn/start` | `sandboxPolicy.type` | `workspaceWrite` |
| `turn/start` | `sandboxPolicy.writableRoots` | 当前 Run Target Path |
| `turn/start` | `sandboxPolicy.networkAccess` | `true` |

`thread/start.sandbox` 与 `turn/start.sandboxPolicy.type` 使用不同枚举格式。协议回归测试必须分别断言，禁止统一转换。

## 4. Run 配置物化

Worker 在 Run 启动前生成独立配置：

```toml
sandbox_mode = "workspace-write"
model = "<resolved-model>"
model_provider = "lingban_runtime"

[sandbox_workspace_write]
network_access = true

[model_providers.lingban_runtime]
name = "<provider-display-name>"
base_url = "<provider-base-url>"
env_key = "<provider-auth-env-name>"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
```

根级 `model`、`model_provider` 必须位于任何 TOML Table 之前。API Key 继续由 Credential Broker 注入环境变量，配置文件只记录变量名。

## 5. 运行模式隔离

| 运行模式 | `HOME` | `CODEX_HOME` | `TMPDIR` | 网络策略 |
|---|---|---|---|---|
| Docker | `/workspace/home` | `/workspace/codex-home` | `/workspace/tmp` | Docker 网络 + Turn Policy |
| Local Process | Run Host `homePath` | Run Host `codexHomePath` | Run Host `tmpPath` | Host 网络 + Turn Policy |

Local Process 必须同时注入 `TARGET_PATH`、`MCP_CONFIG_PATH`、`BRIDGE_CONTEXT_PATH`、`RUNTIME_CONFIG_PATH` 和 Session Pack Host Paths。禁止继承 Worker 进程的共享 `HOME/CODEX_HOME`。

标准镜像包含：

| 工具 | 用途 |

## 7. 测试门禁

| 验收项 | 判定条件 |
|---|---|
| TOML 物化 | 同时存在 `sandbox_mode`、`network_access=true`，Provider 根字段顺序正确 |
| App Server 协议 | 每次 `turn/start` 均包含 `networkAccess=true` |
| Run 隔离 | 子进程 `HOME/CODEX_HOME/TMPDIR` 指向当前 Run |
| Docker 路由 | Runner 容器可访问 `https://registry.npmjs.org` |
| Agent 端到端 | Agent 在真实对话中执行公网请求并返回实际结果 |
| 运行治理 | 新容器无 `NET_ADMIN`，不加载 egress firewall |

## 9. 运维约束

1. 启用 `LINGBAN_RUNTIME_EGRESS_FIREWALL_ENABLED=true` 会恢复目标白名单模式，必须同步维护所有 Provider、MCP、包管理器、网页和外部 API 目标。
2. 启用 egress proxy 时必须提供支持动态公网目标的策略，固定 Provider allowlist 无法满足通用 Agent。
3. 新 Runner 镜像发布必须执行容器公网探测和真实 Agent Turn 验收。
4. 生产安全边界继续由独立容器、Run 级目录、workspace-write、凭证租约、审计事件和资源配额承担。
