# 灵办词元 上线审计与发布资产补齐

## 1. 结论

当前版本还不能直接判定为“可正式上线”。

本轮已经补齐了上线急需的交付资产，但仍缺三类决定性条件：

| 类别 | 当前状态 | 是否阻断上线 |
|---|---|---|
| 代码与测试 | 已通过根级 `pnpm.cmd ci:verify` 验证基线 | 否 |
| 发布与托管资产 | 本轮已补齐 production env、systemd、nginx、release 生成脚本 | 否 |
| 真实运行与目标服务器 | 尚无目标服务器接入信息，尚无远端 Docker/Codex/第三方 MCP 实机证据 | 是 |

## 4. 本轮已补齐的上线急需缺口

| 类型 | 文件 | 作用 |
|---|---|---|
| Release 生成 | `infra/scripts/prepare-production-release.mjs` | 统一导出 standalone workspace、复制静态产物、生成 `release/manifest.json` |
| Root script | `package.json` -> `release:prepare` | 一键生成可部署 release 目录 |
| Production env | `infra/deploy/env/*.production.env.example` | API、Worker、Dashboard、Mobile H5 的生产配置模板 |
| Linux 托管 | `infra/deploy/systemd/*.service` | API、Run Worker 的 systemd 常驻模板 |
| 网关入口 | `infra/deploy/nginx/lingban.conf` | Dashboard、Mobile H5、API 的 Nginx 样例 |
| 服务器安装 | `infra/deploy/server/install-release.sh` | Linux 主机上的安装、构建、迁移、切换、重启脚本 |
| 交付说明 | `infra/deploy/README.md` | 发布资产使用说明 |

## 5. 当前可以做什么

当前已经可以：

1. 生成标准 release 目录
2. 在目标 Linux 机器上安装 API / Worker
3. 直接托管 Dashboard / Mobile H5 静态产物
4. 用 systemd + nginx 形成基础线上托管结构

当前还不能：

1. 在未知服务器上直接部署
2. 给出真实可访问地址
3. 宣布运行时主链已经完成生产验收

## 6. 下一步所需外部信息

部署到真实服务器前，还需要以下最小信息：

| 类别 | 必需信息 |
|---|---|
| 主机接入 | `host`、`port`、`user`、认证方式（私钥 / 密码 / 跳板） |
| 域名 | `dashboard`、`mobile`、`api` 三个入口域名，或单域名反代方案 |
| 数据服务 | PostgreSQL 连接串、Redis 连接串、对象存储 endpoint / bucket / key |
| 运行时 | 远端 Docker Engine 是否可用，Runner image 来源是否已可拉取 |
| 密钥 | `LINGBAN_INTERNAL_AUTH_TOKEN`、`LINGBAN_WORKER_OPS_TOKEN`、对象存储密钥 |

## 7. 当前判断

本轮之后，项目状态已经从“只有开发验证”提升到“具备发布资产、等待真实服务器接入”。

距离正式上线，缺口已经收敛到远端环境与实机验收，不再是本地代码结构问题。
