## 2. 当前资产链事实矩阵

| 证据 | 当前实现 | 当前限制 |
|---|---|---|
| `dashboard/mobile runTemplates` | 已固化 `workspaceId/taskVersionId/sessionVersionId/bindings/targetPath` | 仍是前端模板，不是正式资产目录接口 |
| `launch-plan.ts` | 可将模板绑定转换成 `credentialMounts + mcpBindings` | 绑定规则仍嵌在 API 层 |
| `container-runtime.ts` | 可物化 `runtime-config/mcp-config/mcp-bindings/secret-manifest/container-launch-plan` | 尚未由正式 session pack 驱动 |
| 资产总表文档 | 已定义 `session pack` 文件清单、生命周期、继承规则 | 代码层已具备 pack/unpack、import/export、inherit draft、publish、rollback、unpublish 与 worker staging/restore 主链，尚无 signer 与容器内 live consumption |

## 6. 打包执行矩阵

| 步骤 | 执行方 | 输入 | 输出 |
|---|---|---|---|
| 1 | Creator | 原始 session、workspace snapshot、依赖声明 | 资产草稿 |
| 2 | Creator / packer | 脱敏规则、slot schema、mcp requirements | 规范化目录 |
| 3 | packer | 规范化目录 | `canonical session pack` |
| 4 | signer | pack + manifest | 签名摘要、版本记录 |
| 5 | API | 接收 pack 元数据 | `session_versions`、对象存储 key |
| 6 | release gate | validator、回放结果 | 可发布版本 |

## 7. 继承与 fork 执行矩阵

| 场景 | 输入 | 输出 | 规则 |
|---|---|---|---|
| Creator 继承旧资产 | `session_version` | 新 `session_version draft` | 保留 `lineage_parent_version_id` |
| 用户继续派生 | 已完成 `run` | 新 `run` 或新 `session draft` | 运行增量不回写原 pack |
| 回放验证 | 旧 `session_version` + 新运行环境 | replay report | 用于判断可否升级 |
| 回滚 | 旧 `task_version -> session_version` 映射 | 恢复旧发布状态 | 不删除新资产 |

## 14. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| `packages/session-pack` 仅有最小骨架 | 已能做 manifest/pack/validate、导入导出、inherit draft、publish、rollback、unpublish 与 worker staging/restore，但还不能签名与容器内 live 消费 | 资产化主链仍缺关键生产能力 | P0 |
| 工坊/服务目录仍是前端静态数据 | 发布后无法由后端权威分发 | 用户消费链不成立 | P0 |
| `runTemplates` 承担正式版本映射 | 版本激活与回滚不可治理 | Creator 发布不可控 | P0 |
| 运行依赖解析仍耦合在 `launch-plan.ts` | session requirement 无法独立演进 | 资产消费层不稳定 | P1 |
