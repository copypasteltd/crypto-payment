## 4. 正式上传状态机总表

| 状态 | 含义 | 前端表现 | 可流转 |
|---|---|---|---|
| `queued` | 已选中文件，尚未开始 | 本地附件卡片待上传 | `hashing/signing/cancelled` |
| `hashing` | 正在计算摘要或切片 | 显示准备中 | `signing/failed/cancelled` |
| `signing` | 正在请求上传票据 | 显示申请上传中 | `uploading/failed/cancelled` |
| `uploading` | 正在上传文件或分片 | 展示进度、速度、剩余时间 | `verifying/failed/cancelled` |
| `verifying` | 对象已传，等待服务端完成确认 | 进度锁定在 100%，显示登记中 | `ready/failed` |
| `ready` | 已生成 `attachment_ref` | 可随消息提交 | `submitted/removed` |
| `submitted` | 已绑定到一条消息 | 对话流显示附件卡片 | 终态 |
| `failed` | 上传或确认失败 | 可重试或删除 | `queued/signing/uploading/removed` |
| `cancelled` | 用户主动取消 | 卡片变灰或移除 | `queued/removed` |
| `removed` | 已从草稿区删除 | 不再显示 | 终态 |

## 5. 大文件策略矩阵

| 文件等级 | 判定口径 | 传输策略 | 交互要求 | 当前状态 |
|---|---|---|---|---|
| 小文件 | `<= 10MB` | 单请求直传 | 进度条可简化 | 未实现 |
| 中文档 | `10MB ~ 200MB` | multipart 分片上传 | 需显示分片进度、暂停/恢复能力 | 未实现 |
| 大文件 | `200MB ~ 2GB` | multipart + 后台继续传输 | 需离开页面后可恢复 | 未实现 |
| 超大文件 | `> 2GB` 或触达 workspace 配额阈值 | 默认拒绝或要求压缩/外链 | 明确给出限制和替代方案 | 未实现 |
| 批量材料 | 多文件同时选择 | 并发 2~4 路上传队列 | 可单文件重试，不阻塞整批提交 | 未实现 |

## 8. 正式提交链路总表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | 本地文件 | 生成 `client_attachment_draft` | 本地草稿对象 |
| 2 | 前端 -> API | 文件元数据 | `createRunUploadSession()` | `upload_ticket` |
| 3 | 前端 -> 对象存储 | `upload_ticket + file/chunks` | 上传内容 | 对象已写入 |
| 4 | 前端 -> API | `upload_session_id/checksum/storage_key` | `completeRunUploadSession()` | `attachment_ref` |
| 5 | 前端 -> API/Realtime | 文本 + `attachment_ref[]` | `sendRunMessage()` | 用户消息 |
| 6 | API -> Bridge | 已提交消息 | 派发到 runtime | Codex 可读附件引用 |
| 7 | Bridge/Worker | `attachment_ref` | 物化到 `inputs/` 或只读映射 | 运行目录中的实际文件 |

## 9. 大文件恢复与断点续传矩阵

| 故障场景 | 当前状态 | 正式行为 |
|---|---|---|
| 页面刷新 | 无恢复 | 根据 `upload_session_id` 恢复上传状态 |
| 网络中断 | 无恢复 | 分片级重试，保留已成功分片 |
| 签名过期 | 无恢复 | 自动续签未完成分片 |
| 完成确认失败 | 无恢复 | 保持 `verifying/failed`，支持重新 `complete` |
| 用户取消 | 无恢复 | 中止请求并将未提交附件转 `cancelled` |
| 文件已上传但消息未发送 | 无恢复 | 保留 `ready` 态附件，等待用户重发文本 |

## 13. 错误码与回退矩阵

| 场景 | 正式错误码建议 | 前端动作 |
|---|---|---|
| 文件超限 | `UPLOAD_SIZE_EXCEEDED` | 阻止上传并给出大小限制 |
| 类型不允许 | `UPLOAD_TYPE_REJECTED` | 说明支持的格式 |
| workspace 配额不足 | `UPLOAD_QUOTA_EXCEEDED` | 阻止提交并提示清理或升级 |
| 上传会话过期 | `UPLOAD_SESSION_EXPIRED` | 自动续签或提示重试 |
| 对象校验失败 | `UPLOAD_CHECKSUM_MISMATCH` | 回退到 `failed` 并允许重传 |
| 提交消息时附件未完成 | `ATTACHMENT_NOT_READY` | 禁止发送或自动等待 |

## 14. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无上传会话与进度模型 | 双端无法正式补材料 | 输入材料链断裂 | P0 |
| 大文件策略缺失 | 无法承载真实业务材料 | 企业用户不可用 | P0 |
| 草稿恢复缺失 | 页面刷新或弱网会丢附件 | 用户体验差 | P0 |
| Bridge 回流附件为空 | 会话流无法展示附件事实 | 结果解释和审计弱化 | P1 |
| SDK 无统一上传门面 | 双端接线成本高 | 行为不一致 | P1 |
