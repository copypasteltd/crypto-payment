## 2. 当前静态目录事实矩阵

| 终端 | 当前对象 | 当前字段特征 | 当前问题 |
|---|---|---|---|
| Dashboard | `Workshop`、`DashboardService` | 含封面、受众、摘要、标签、默认服务、目标路径、授权说明 | 全部本地静态常量 |
| Mobile | `MobileWorkshop`、`MobileService` | 更轻量，强调 owner、badge、summary、eta、auth | 与 Dashboard 字段不完全同构 |
| Mobile 可见性 | `workshopVisibility`、`serviceVisibility` | 按 workspace 本地过滤 | 无服务端治理 |
| 双端启动模板 | `buildDashboardRunInput()`、`buildMobileRunInput()` | 前端直接拼 `CreateRunInput` | 缺少服务端 launch template |

## 3. 目录查询执行矩阵

| 接口 | 输入 | 核心动作 | 输出 |
|---|---|---|---|
| `GET /v1/workshops` | `workspace_id`、`entry_surface`、`q`、`tag`、`scope` | 过滤当前工作区可见工坊并做搜索排序 | `workshop_catalog_page` |
| `GET /v1/workshops/:workshopId` | `workshopId`、`workspace_id` | 返回工坊详情和默认服务摘要 | `workshop_detail` |
| `GET /v1/workshops/:workshopId/services` | `workshopId`、`workspace_id` | 返回该工坊下当前可实例化服务 | `service_catalog_entry[]` |
| `GET /v1/services/:serviceId` | `serviceId`、`workspace_id` | 返回服务详情、授权要求、版本摘要 | `service_detail` |
| `POST /v1/services/:serviceId/launch-template` | `workspace_id`、`entry_surface` | 解析当前服务默认绑定版本和能力依赖 | `launch_template` |

## 11. 当前缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 工坊目录仍是前端静态数据 | 双端都读本地常量 | Creator 发布无法驱动目录变化 | P0 |
| launch template fallback 未退场 | 主链已由后端模板接口承接，但双端仍保留本地 fallback | 版本切换和灰度发布的最终裁决仍需彻底收口到服务端 | P0 |
| 可见性规则只在前端判断 | `workspaceCatalog.ts` 本地过滤 | 无法形成正式治理边界 | P0 |
| 双端字段未完全同构 | Dashboard/H5 字段结构不一致 | 统一目录 API 成本上升 | P1 |

## 13. 当前不可宣称完成的启动模板能力表

| 能力 | 当前原因 | 当前结论 |
|---|---|---|
| 服务端版本切换 | 主链已由 `launch-template` 决定，fallback 仍保留前端模板 | 不可宣称前端 fallback 已完全退场 |
| 服务端 targetPath 模板 | 主链由后端返回 `targetRoot` 并生成 target path，fallback 仍保留本地拼接 | 不可宣称路径策略已彻底统一 |
| 服务端 binding 解析 | 主链已由后端返回 `bindings`，fallback 仍保留本地常量 | 不可宣称启动依赖已完全脱离前端模板 |
