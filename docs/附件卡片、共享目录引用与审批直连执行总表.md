## 7. 正式对象表

### 7.1 附件 / 引用对象表

| 对象 | 主键 | 核心字段 | 说明 |
|---|---|---|---|
| `attachment_card` | `card_id` | `run_id`、`message_id`、`attachment_refs[]`、`state`、`uploaded_by` | 会话内附件卡片 |
| `workspace_file_reference` | `ref_id` | `workspace_id`、`file_id`、`path`、`label`、`mode`、`requested_by` | 对共享目录文件的引用 |
| `attachment_inline_action` | `action_id` | `card_id`、`action_type`、`state`、`last_error` | 卡片上的上传/删除/重传动作 |

### 7.2 审批直连对象表

| 对象 | 主键 | 核心字段 | 说明 |
|---|---|---|---|
| `approval_resolution_command` | `cmd_id` | `run_id`、`approval_id`、`decision`、`note`、`requested_by_user_id` | 前端发起的审批决策命令 |
| `approval_card_state` | `approval_id` | `state`、`processing`、`decided_at`、`decided_by`、`error` | 前端会话内审批卡片状态 |
| `inline_action_receipt` | `receipt_id` | `run_id`、`item_id`、`action_type`、`status`、`created_at` | 记录消息流中一次直连动作执行结果 |

## 9. 附件卡片正式执行表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | 本地文件 | 调上传票据接口 | `upload_ticket` |
| 2 | 前端 | `upload_ticket + file` | 直传对象存储 | `storage_key/checksum` |
| 3 | API | 上传完成参数 | 创建 `input_material/message_attachment` | `attachment_ref` |
| 4 | 前端 | 文本 + `attachment_ref[]` | `sendRunMessage()` | 普通消息 + `attachment.card` |

## 10. 共享目录引用正式执行表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | `workspaceId` | 打开共享目录文件树 | `workspace file list` |

## 11. 审批直连正式执行表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | `approvalId + decision + note?` | 调 HTTP 或 realtime `approve()` | `approval_resolution_command` |
| 2 | 前端 | 提交中 | 卡片进入 processing 态，按钮禁用 | 防重复点击 |
| 3 | API | 决策命令 | 精确命中 `approval_id` 并回写审批状态 | 更新 run 快照 |
| 4 | API | 更新后状态 | 广播 `run.status.changed` + `conversation.message` + `approval.resolved` | 前端同步 |
| 5 | 前端 | 收到结果 | 卡片改为已确认 / 已驳回，并写入操作者和时间 | 对话流闭环 |

## 12. 前端交互状态矩阵表

| 状态 | 附件卡片 | 审批卡片 | 共享目录引用 |
|---|---|---|---|
| `idle` | 可上传 | 可确认/驳回 | 可选择文件 |
| `processing` | 上传中/完成登记中 | 审批处理中 | 引用创建中 |
| `resolved` | 已绑定到消息 | 已确认/已驳回 | 已引用 |
| `failed` | 支持重传/删除 | 支持重试决策 | 支持重新选择 |

## 13. 错误与回退矩阵表

| 场景 | 当前行为 | 正式行为 |
|---|---|---|
| 上传失败 | 当前无 | 卡片进入 failed 态，支持重传 |
| 共享文件无权限 | 当前无 | 提示权限不足，不创建引用 |
| 审批重复提交 | 当前可能语义模糊 | 后端幂等拒绝，卡片显示已处理 |
| 审批 `approvalId` 不存在 | 当前 service 可能仍处理首个 pending | 返回结构化错误，不回退到其他审批 |
| realtime 发送审批后断线 | 当前无 UI 反馈 | processing 态等待 ack，超时转 failed |

## 17. 验收判定表

| 验收项 | 判定标准 |
|---|---|
| 附件可正式进入消息流 | 用户可上传文件并在对话流中看到附件卡片 |
| 共享目录可引用 | 用户可从 workspace 共享目录选择文件并引用到当前任务 |
| 审批可卡片内直连 | 用户无需手工发文本，即可在卡片内确认或驳回审批 |
| `approvalId` 精确生效 | 多审批场景下不会误处理其他 pending approval |
| 双端对齐 | H5 与 Dashboard 都支持相同的附件/审批直连交互 |
