## 3. 实时通道分层总表

| 层级 | 通道 | 当前实现 | 作用 |
|---|---|---|---|
| L1 | WS | `GET /ws/runs/:runId` | 主实时订阅通道 |
| L2 | SSE | `GET /v1/runs/:runId/stream` | 浏览器回退通道 |
| L3 | HTTP | `POST /messages /approvals /cancel` | 非实时或恢复性动作通道 |
| L4 | Internal Bridge Ingest | `/internal/runs/:runId/events` | bridge 到 API 的事件回流 |
| L5 | Event Bus | `InMemoryRunEventBus` | API 内部广播与 backlog |
| L6 | SDK Client | `createRunsRealtimeClient()` | 前端统一接入层 |

## 4. 客户端实时消息协议总表

| `type` | 必填字段 | 当前语义 |
|---|---|---|
| `runs.subscribe` | `runId` | 建立实时订阅或重新请求 snapshot |
| `runs.sendMessage` | `runId`、`payload.text`、`payload.attachments?` | 发送用户消息 |
| `runs.approve` | `runId`、`payload.approved`、`payload.note?` | 提交审批结果 |
| `runs.cancel` | `runId`、`reason?` | 请求取消实例 |

## 5. 服务端实时消息协议总表

| `type` | 必填字段 | 当前语义 |
|---|---|---|
| `runs.snapshot` | `payload: RunSnapshot` | 返回当前完整快照 |
| `runs.event` | `payload: BridgeEvent` | 推送单条增量事件 |
| `runs.ack` | `runId`、`ok` | 对订阅或动作做确认 |
| `runs.error` | `error`、`runId?` | 返回错误信息 |

## 6. WS 建连与首包时序总表

| 步骤 | 当前责任模块 | 当前行为 |
|---|---|---|
| 1 | SDK | 连接 `/ws/runs/:runId` |
| 2 | API socket route | 校验 `runId` 参数 |
| 3 | API socket route | `runsService.getRun(runId)` 校验 run 存在 |
| 4 | API socket route | 发送 `runs.snapshot` |
| 5 | API socket route | 遍历 `runEventBus.list(runId)` 发送 backlog |
| 6 | API socket route | 发送 `runs.ack` |
| 7 | API socket route | `subscribe(runId, listener)` 注册订阅 |
| 8 | SDK | 在 `onOpen` 后主动再次发送 `runs.subscribe` |

## 7. SSE 建连与首包时序总表

| 步骤 | 当前责任模块 | 当前行为 |
|---|---|---|
| 1 | 前端 fallback | 建立 `EventSource` 到 `/v1/runs/:runId/stream` |
| 2 | API route | 返回 `text/event-stream` |
| 3 | API route | 推送 `runs.snapshot` 帧 |
| 4 | API route | 推送 backlog `runs.event` 帧 |
| 5 | API route | `subscribe(runId)` 注册监听 |
| 6 | API route | 连接关闭时 `unsubscribe()` |

## 8. 消息投递链路矩阵表

| 动作 | 发起端 | API 当前入口 | API 当前处理 | bridge 当前处理 |
|---|---|---|---|---|
| 用户发消息 | WS / HTTP | `runs.sendMessage` 或 `POST /messages` | `runsService.sendMessage()` 写聚合、发 event、dispatch bridge command | 接收 `sendMessage` |
| 审批 | WS / HTTP | `runs.approve` 或 `POST /approvals` | `runsService.approve()` 更新 approval/run 状态、发 event、dispatch bridge command | 接收 `approve` |
| 取消 | WS / HTTP | `runs.cancel` 或 `POST /cancel` | `runsService.cancel()` 更新状态、dispatch cancel | 接收 `cancel` |
| 文件同步 | API / 诊断 | `syncFiles` bridge command | 进入 registry 队列 | bridge 扫描并回传 `files.synced` |
| 产物刷新 | API / 诊断 | `flushArtifacts` bridge command | 进入 registry 队列 | bridge 回传 `artifact.ready` |

## 9. 事件总线存储与回放总表

| 维度 | 当前实现 | 当前限制 |
|---|---|---|
| 内存结构 | `Map<runId, RunEventEnvelope[]>` | 单进程内存 |
| 监听结构 | `Map<runId, Set<listener>>` | 单节点广播 |
| 持久化 | `events/<runId>.jsonl` 每行一条 envelope | 无压缩、无分段 |
| 启动恢复 | 启动时扫描全部 `.jsonl` 重建内存 | 大规模时启动变慢 |
| eventId | `evt_${randomUUID()}` | 无顺序游标 |
| backlog 查询 | `list(runId)` 返回全量 | 无分页、无 cursor |

## 10. 事件到快照投影规则总表

| 事件 | 当前投影规则 | 去重或覆盖逻辑 |
|---|---|---|
| `run.status.changed` | 更新 `run.status` 和 `statusReason` | 同状态允许更新时间与原因 |
| `conversation.message` | 追加到 `messages` | 按 `messageId` 去重 |
| `approval.requested` | upsert 到 `approvals` | 按 `approvalId` |
| `artifact.ready` | upsert 到 `artifacts` | 按 `artifactId` |
| `files.synced` | 全量替换 `files` | 无增量合并 |
| `file.changed` | upsert 到 `files` | 按 `path` |
| `run.failed` | 强制投影为 `FAILED` | `error` 写入 `statusReason` |
| `heartbeat` | 不修改快照 | 仅用于活性 |

## 11. ack 与错误处理矩阵表

| 场景 | 当前响应 |
|---|---|
| WS 首次连接成功 | `runs.ack` |
| `runs.subscribe` 成功 | 再发一次 `runs.snapshot` + `runs.ack` |
| `runs.sendMessage` 成功 | `runs.ack` |
| `runs.approve` 成功 | `runs.ack` |
| `runs.cancel` 成功 | `runs.ack` |
| 参数解析失败 | `runs.error` |
| `runId` 与 URL 不一致 | `runs.error` |
| run 不存在 | `runs.error` 并关闭 socket |

## 12. 连接关闭与清理总表

| 场景 | 当前行为 |
|---|---|
| WebSocket close | 调用 `unsubscribe()` |
| WebSocket error | 调用 `unsubscribe()` |
| SSE close | `request.raw.on("close")` 中 `unsubscribe()` 并 `reply.raw.end()` |
| SDK 主动关闭 | 移除监听器并 `socket.close(1000, "client.close")` |

## 13. 前端接入能力矩阵表

| 终端 | 当前实时能力 | 当前缺口 |

## 14. 幂等、顺序与一致性总表

| 维度 | 当前机制 | 当前缺口 |
|---|---|---|
| message 幂等 | `messageId` 去重 | 客户端重发未带客户端 id |
| event 幂等 | `eventId` 仅服务端生成 | 客户端无法按 cursor 去重 |
| backlog 顺序 | 依赖 `.jsonl` 追加顺序 | 无跨节点全局顺序 |
| WS 订阅一致性 | 首次 snapshot + backlog + live push | 无水位线协议 |
| SSE 一致性 | snapshot + backlog + live push | 无 `Last-Event-ID` 恢复 |

## 15. 认证与权限缺口总表

| 缺口 | 当前影响 |
|---|---|
| WS / SSE 无正式认证 | 任意客户端理论上可订阅 run |
| `runId` 存在即允许订阅 | 无工作区成员边界 |
| internal bridge ingest 无正式签名校验 | 事件回流链路安全不足 |
| 无 rate limit | 高并发下消息面可能失控 |

## 16. 扩展目标总表

| 目标能力 | 正式要求 |
|---|---|
| reconnect/backoff | SDK 统一实现自动重连和抖动退避 |
| cursor/watermark | 建立按 `eventId` 或序列号恢复 |
| 多节点广播 | Redis/NATS/Kafka/消息中间件 |
| SSE `Last-Event-ID` | 支持断点续传 |
| WS 认证 | token + workspace ACL |
| 事件签名 | internal bridge 事件签名或 mTLS |

## 18. 当前不可宣称完成的实时能力表
