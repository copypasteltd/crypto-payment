## 4. 当前入口装载模型表

| 终端 | 当前入口 | 当前装载模型 | 当前问题 |
|---|---|---|---|
| Dashboard | `AppProviders -> BrowserRouter -> AppRouter -> DashboardShell` | QueryClient 初始化后立即渲染所有同步路由体系 | 缺 bootstrap loading；缺 route lazy |
| Mobile H5 | `App -> QueryClientProvider -> Taro pages` | 读取本地 store 后直接渲染页面 | 缺 auth/bootstrap；缺首屏预取 |
| Dashboard 实例页 | Query + realtime + 轮询并存 | 轮询 10 秒 + 实时合流 | 页面压力偏高 |
| Mobile 任务/文件页 | Query + realtime + 轮询并存 | 详情与文件树都 10 秒轮询 | 文件页网络开销偏高 |

## 5. 预算拆分表

| 场景 | 总预算 | 预算拆分建议 |
|---|---|---|
| Dashboard 工坊首屏 | 2.5s | `HTML/CSS/JS 首包 <= 900ms`、`bootstrap <= 600ms`、`首屏数据 <= 700ms`、`绘制余量 <= 300ms` |
| Mobile H5 工坊首屏 | 2.5s | `首包 <= 1000ms`、`工作区恢复 <= 400ms`、`目录数据 <= 700ms`、`绘制余量 <= 400ms` |
| 服务详情打开 | 1s | `路由切换 <= 100ms`、`骨架可见 <= 200ms`、`详情 query <= 500ms`、`动画与稳定 <= 200ms` |
| 消息本地回显 | 100ms | `输入处理 <= 16ms`、`本地消息插入 <= 50ms`、`按钮态切换 <= 34ms` |
| 文件下载启动反馈 | 300ms 可见反馈 | `点击到 loading 态 <= 100ms`、`URL 构造与调用 <= 200ms` |

## 6. 代码层性能证据表

| 位置 | 当前实现 | 结论 |
|---|---|---|
| `app/dashboard/src/app/providers/AppProviders.tsx` | 统一 `QueryClient`，仅配置 `retry/staleTime` | 性能层基础存在，但缺进一步调优参数 |
| `app/mobile/src/app.tsx` | 与 Dashboard 使用同口径 Query 配置 | 双端策略一致，但仍偏基础 |
| `app/dashboard/src/app/router/AppRouter.tsx` | `CreatorPage`、`InstancesPage`、`WorkshopsPage` 均同步 import | 当前没有路由分包 |
| `app/dashboard/src/pages/instances/InstancesPage.tsx` | 多个 query 使用 `refetchInterval:10000` | 实例页是主要轮询热点 |
| `app/mobile/src/pages/workshops/index.tsx` | 首页 `listRuns()` 10 秒轮询补最近任务 | 首页额外背负 live runs 代价 |
| `app/mobile/src/pages/tasks/detail.tsx` | 详情 `getRun()` 10 秒轮询 + realtime | 有补偿链，但无分级 pause |
| `app/mobile/src/pages/tasks/files.tsx` | `getRun()`、`listRunFileTree()`、`readRunFile()` 协同 | 文件页网络密度最高 |

## 7. 轮询与实时压力矩阵

| 页面 | 当前轮询项 | 当前频率 | 风险 | 正式建议 |
|---|---|---|---|---|
| Dashboard 实例页 | `listRuns`、`getRun`、`listRunFileTree` | 10s | 多 query 同时拉取 | 详情页优先依赖 realtime，轮询仅作兜底 |
| Mobile 工坊页 | `listRuns` | 10s | 首页为最近任务承担额外网络消耗 | 将最近任务抽成可见时加载或后台低频刷新 |
| Mobile 我的页 | `listRuns` | 10s | 与首页重复拉 runs | 改为 metrics/profile 专用 query |
| Mobile 任务详情 | `getRun` | 10s | 长时会话成本高 | 聚焦 realtime，弱网时降频 |
| Mobile 文件页 | `getRun`、`listRunFileTree`、`readRunFile` | 10s | 文件页最容易形成重载 | 文件预览只在选中后读，目录增量同步优先 realtime |

## 8. 首屏与恢复性能矩阵

| 场景 | 当前状态 | 影响 | 正式要求 |
|---|---|---|---|
| Dashboard 首屏 | 无 loading shell | 可能先渲染后回滚 | 引入 bootstrap shell 与关键 query 预取 |
| Mobile 首屏 | 仅本地 store 恢复 | 首屏上下文合法性不可控 | 引入 auth/workspace bootstrap |
| 回到任务页 | 草稿可本地恢复 | 消息与文件恢复时间不稳定 | 1 秒内恢复最近消息、草稿、连接状态 |
| 切换工作区 | 当前主要切本地 store | 可能残留旧 query | 增加批量失效与预热 |

## 9. 渲染与拆包矩阵

| 主题 | 当前状态 | 风险 | 正式建议 |
|---|---|---|---|
| Dashboard 路由分包 | 无 | 首包持续膨胀 | 对 `CreatorPage`、`InstancesPage` 做 lazy import |
| Mobile 页面拆分 | 由 Taro Pages 自然分 page | 相对可控 | 保持页面边界，不把重逻辑堆回 `app.tsx` |
| 长列表优化 | 当前无虚拟列表 | 实例列表、文件列表增长后会卡顿 | 当实例/文件量上升时增加虚拟化或分页 |
| 大型页面 memo 化 | 已有大量 `useMemo` | 方向正确 | 需要避免依赖项过宽导致重复计算 |

## 10. 交互响应矩阵

| 交互 | 当前实现 | 当前结论 | 正式要求 |
|---|---|---|---|
| 搜索输入 | 多页面本地 `useState + useMemo` 过滤 | 当前足够原型态 | 大列表时增加防抖与分段搜索 |
| 工坊筛选 | 本地 `useState` + 同步过滤 | 响应直接 | 保持 500ms 内反馈 |
| 消息发送 | 本地草稿 + realtime 优先 + HTTP fallback | 链路完整 | 本地回显与失败态需进一步显式化 |
| 文件路径切换 | 本地状态切换 + query 预览 | 基础可用 | 路径校验与预览更新不应阻塞主线程 |
| 下载按钮 | 直接 `window.open` / `Taro.downloadFile` | 体验基础可用 | 要有即时 loading/成功/失败反馈 |

## 11. 资源与样式成本矩阵

| 主题 | 当前状态 | 风险 | 正式建议 |
|---|---|---|---|
| `prototype.css` | 双端都较大且承载页面样式 | 样式解析与维护成本高 | 拆成 `base/business/page` 三层 |
| Logo / 插图资源 | 已接入多张 SVG/PNG | 当前可控 | 后续需要按首屏优先级懒加载非关键图 |
| 图标体系 | 主要为内联 sprite 或位图 | 图标扩张后重复成本高 | 建统一 Icon 层与按需资源 |
