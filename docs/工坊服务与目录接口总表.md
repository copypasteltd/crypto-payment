| 字段 | 内容 |
|---|---|
| 文档名称 | 工坊服务与目录接口总表 |

## 2. 当前前端目录模型证据表

| 终端 | 当前模型 | 当前字段特点 | 当前差距 |
|---|---|---|---|
| Dashboard | `Workshop`、`DashboardService` | 含封面、受众、摘要、标签、默认服务、目标路径、授权说明 | 目录数据仍是本地静态对象 |
| Mobile | `MobileWorkshop`、`MobileService` | 更轻量，强调 owner、badge、summary、eta、auth | 目录数据仍是本地静态对象 |
| Mobile 可见性层 | `workshopVisibility`、`serviceVisibility` | 按 `workspaceId` 做本地过滤 | 缺正式服务端可见性策略 |

## 3. 正式目录资源分层总表

| 资源 | 面向对象 | 职责 | 是否直接给前端 |
|---|---|---|---|
| `workshop_catalog_entry` | 轻度用户、重度用户 | 工坊卡片信息，用于列表与搜索 | 是 |
| `workshop_detail` | 工坊详情页 | 工坊介绍、默认服务、入口说明、标签、路径提示 | 是 |
| `service_catalog_entry` | 工坊内服务卡片 | 可实例化服务的摘要卡 | 是 |
| `service_detail` | 启动面板 | 启动前说明、授权要求、路径、默认版本、预估耗时 | 是 |
| `workspace_visibility_rule` | 服务端策略 | 决定当前工作区看到哪些工坊和服务 | 否 |
| `launch_template` | 运行前置配置 | 为前端生成 `CreateRunInput` 的服务端模板 | 可选直接下发 |

## 6. 目录接口清单总表

| Method | Path | Query / Body | 主要响应 | 主要调用方 | 当前状态 |
|---|---|---|---|---|---|
| `GET` | `/v1/workshops` | `scope?`、`q?`、`tag?`、`page?`、`page_size?` | `workshop_catalog_page` | Dashboard 工坊页、H5 工坊页 | 目标接口 |
| `GET` | `/v1/workshops/:workshopId` | `workshopId` | `workshop_detail` | Dashboard 工坊详情、H5 工坊详情 | 目标接口 |
| `GET` | `/v1/workshops/:workshopId/services` | `workshopId`、`status?` | `service_catalog_entry[]` | Dashboard/H5 工坊详情 | 目标接口 |
| `GET` | `/v1/services/:serviceId` | `serviceId` | `service_detail` | Dashboard 服务启动页、H5 服务详情页 | 目标接口 |
| `POST` | `/v1/services/:serviceId/launch-template` | `workspace_id`、`entry_surface` | `launch_template` | Dashboard/H5 创建 run 前获取模板 | 目标接口 |
| `GET` | `/v1/workshops/recent` | `limit?` | `workshop_catalog_entry[]` | H5 首屏、Dashboard 首屏摘要 | 目标接口 |
| `GET` | `/v1/workshops/recommended` | `workspace_id?`、`entry_surface?` | `workshop_catalog_entry[]` | H5 轻度入口 | 目标接口 |

## 10. 目录可见性规则总表

| 规则维度 | 当前前端证据 | 正式服务端规则建议 |
|---|---|---|
| 按工作区类型可见 | `workshopVisibility`、`serviceVisibility` | 由 `workspace_visibility_rule` 表或策略引擎统一判定 |
| 按工作区权限可见 | 当前无 | 工坊/服务可绑定最小角色 |
| 按发布状态可见 | 当前无 | `draft` 不对终端暴露，`active` 才进入目录 |
| 按入口面可见 | 当前无 | H5 / Dashboard / 小程序可分别控制暴露 |
| 按灰度名单可见 | 当前无 | Creator 灰度包只对允许的工作区与成员可见 |

## 12. 当前阻塞总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 工坊目录完全前端本地化 | 工坊和服务都在 `dashboardData.ts` / `mobileData.ts` | 无法由 Creator 发布驱动前端目录 | P0 |
| 可见性规则在前端硬编码 | `workspaceCatalog.ts` 按字符串判断工作区可见性 | 无法形成统一治理边界 | P0 |
| launch template fallback 未退场 | 主链已由后端模板接口承接，但双端仍保留本地 fallback | 运行版本切换和灰度发布的最终裁决仍需彻底收口到服务端 | P0 |
| H5 与 Dashboard 字段不统一 | Mobile 和 Dashboard 的工坊字段结构不同 | 双端目录接口难统一 | P1 |
