## 7. 消息附件上传链路总表

| 步骤 | 执行方 | 输入 | 核心动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | 选择本地文件 | 读取文件名、大小、类型 | 上传前元数据 |
| 2 | API | `POST /v1/runs/:runId/attachments/upload-url` | 校验 run 与工作区权限，返回预签名上传票据 | `upload_ticket` |
| 3 | 前端 | `upload_ticket` + 文件内容 | 直传对象存储或走直传接口 | 对象存储文件 |
| 4 | API | `POST /v1/runs/:runId/attachments/complete` | 生成 `input_material` 和 `message_attachment` 草稿 | `attachment_ref` |
| 5 | 前端 | `attachment_ref` + 消息正文 | 调用 `sendRunMessage()` | 对话消息写入成功 |
| 6 | worker/bridge | 新附件引用 | 挂载或同步到 `inputs/` | Codex 可在同一会话里读取材料 |

## 8. 建议上传接口清单总表

| Method | Path | 主要请求字段 | 主要响应字段 | 用途 |
|---|---|---|---|---|
| `POST` | `/v1/runs/:runId/attachments/upload-url` | `filename`、`mime_type`、`size_bytes`、`material_kind` | `upload_ticket` | 获取上传票据 |
| `POST` | `/v1/runs/:runId/attachments/complete` | `upload_id`、`storage_key`、`checksum`、`label` | `attachment_ref` | 完成上传登记 |
| `GET` | `/v1/runs/:runId/attachments` | 分页参数 | `message_attachment[]` | 查看当前 run 附件 |
| `DELETE` | `/v1/runs/:runId/attachments/:attachmentId` | `attachmentId` | `{ ok: true }` | 删除或撤回附件 |

## 10. 消息发送与附件引用关系总表

| 发送模式 | 当前状态 | 正式建议 |
|---|---|---|
| 纯文本消息 | 已实现 | 维持现状 |
| 文本 + 已上传附件引用 | 契约层已支持 | 作为主路径 |
| 仅附件无文本 | 当前 schema 不允许 `text` 为空 | 建议保留最少说明文本，避免上下文断裂 |
| 多附件批量消息 | 契约层允许 `attachments[]` | 前端需支持多文件选择与上传队列 |

## 11. 附件挂载与容器内路径策略总表

| 物料类型 | 建议容器内路径 | 说明 |
|---|---|---|
| 文档类输入 | `/workspace/inputs/docs/<filename>` | 文本、PDF、表格、合同等 |
| 图片类输入 | `/workspace/inputs/images/<filename>` | 品牌图、参考图、素材图 |
| 压缩包/素材集 | `/workspace/inputs/packages/<filename>` | 供 Codex 解压或归档处理 |
| browser state / cookie | `/workspace/secrets/browser/<filename>` | 敏感材料，不直接放 inputs |
| 工作区共享文件引用 | `/workspace/inputs/shared/<filename>` | 从 workspace 资产库映射 |

## 13. 权限控制矩阵总表

| 操作 | 最低权限 | 关键校验 |
|---|---|---|
| 上传消息附件 | `operator` | 当前工作区可访问该 run，附件大小与类型符合策略 |
| 查看附件元数据 | `member` | 当前工作区拥有该 run |
| 下载附件 | `member` | 附件可见性允许且属于该 run/workspace |
| 删除附件 | 上传人、run owner 或 admin | 避免删除别人正在使用的关键材料 |
| 挂载共享物料 | `operator` + 共享物料读取权 | 共享物料本身的授权独立校验 |

## 14. 当前缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 附件上传接口缺失 | 只有 schema，没有上传链 | 对话内补材料无法正式化 | P0 |
| 附件与输入物料对象缺失 | 没有 `input_material` / `message_attachment` 正式模型 | 无法追踪材料来源、权限、版本 | P0 |
| 输入物料挂载策略未实现 | `inputs/` 已建目录，但没有物料同步逻辑 | Codex 不能稳定读取用户补传材料 | P0 |
| 富预览能力不足 | 当前主要是文本 read 与直接下载 | H5/Dashboard 文件体验不完整 | P1 |
