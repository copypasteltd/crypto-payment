## 2. 顶层调用方向矩阵

| 上游 | 下游 | 当前调用方式 | 性质 |
|---|---|---|---|
| Dashboard/Mobile 页面 | `packages/api-sdk` | HTTP/WS client 调用 | 前端 -> 接入层 |
| `packages/api-sdk` | API | HTTP / WS / SSE | 外部边界 |
| API routes | `RunsService` / `RunFileAccessService` / `bridgeRegistry` / `runEventBus` | 直接函数调用 | 控制层 -> 业务层 |
| `RunsService` | `runsRepository` / `runEventBus` / `bridgeRegistry` / `runOrchestrator` | 直接调用 | 业务层 -> 存储/编排 |
| `runOrchestrator` | Worker / Bridge | 当前进程内编排或子进程拉起 | 编排边界 |
| Worker | `workspace-preparer` / `run-lifecycle` / `container-runtime` / `bridge-runner` | 同进程函数调用 | 运行时准备链 |
| Bridge | `CodexSession` / `FileWatcher` / `ArtifactPublisher` / `ApiConnector` | 同进程对象协作 | 容器内执行链 |

## 4. Run 主链调用细分矩阵

| 阶段 | 当前函数 | 输入 | 输出 |
|---|---|---|---|
| 创建 run | `RunsService.createRun()` | `CreateRunInput` | `CreateRunResponse` |
| 启动载荷生成 | `buildStartRunJobPayload()` | `run + prompt + bindings` | `StartRunJobPayload` |
| 运行编排 | `runOrchestrator.startRun(runId)` | `runId` | 异步启动 worker/bridge |
| workspace 准备 | `prepareRunWorkspace()` | `runId/workspaceId/targetPath` | `PreparedRunWorkspace` |
| context 改写 | `buildHostBridgeSessionContext()` / `buildContainerBridgeSessionContext()` | payload + workspace | `BridgeSessionContext` |
| runtime 物化 | `materializeRunRuntime()` | payload + workspace + contexts | runtime files + launch plan |
| bridge 启动 | `startLocalBridgeProcess()` | `StartRunJobResult` | health/control handle |
| Codex 会话启动 | `CodexSession.start()` | context + env | PTY + events |
| 事件回流 | `ApiConnector -> /internal/runs/:runId/events` | `BridgeEvent[]` | 更新 run snapshot |

## 6. 同步与异步边界矩阵

| 边界 | 当前方式 | 说明 |
|---|---|---|
| HTTP 请求 | 同步请求 -> promise | 标准 API 边界 |
| WebSocket | 长连接 + push | 实时状态与消息 |
| SSE | 单向流 | WS 不可用时回退 |
| Worker 准备链 | `async/await` | 目录创建、文件写入 |
| Bridge 子进程 | `spawn()` + health polling | API 与 bridge 解耦点 |
| Codex CLI | PTY | 运行时最深异步边界 |
| 文件监听 | `chokidar` | 异步事件投递 |

## 8. 当前禁止跨层职责矩阵

| 模块层 | 当前应避免的职责漂移 | 原因 |
|---|---|---|
| routes 层 | 直接改 repository | 保持控制层薄 |
| `RunsService` | 直接关心 React Query / 页面模型 | 保持后端纯业务 |
| Worker | 直接生成前端展示文案 | 保持运行时只产出结构化物料 |
| Bridge | 决定工作区授权 | 授权应在 API 侧完成 |
| 前端 adapter | 推导业务真相状态 | 应只消费后端权威状态 |

## 9. 高耦合点拆分执行矩阵

| 耦合点 | 当前位置 | 收敛目标 |
|---|---|---|
| run 持久层与 service 耦合 | `RunsService <-> runsRepository` | `packages/db + Repository interface` |
| MCP 绑定解析与 runtime 物化分散 | `launch-plan.ts`、`container-runtime.ts`、`mcp-materializer.ts` | `packages/mcp` |
| secret 规则分散 | `launch-plan.ts`、`run-lifecycle.ts`、`secret-loader.ts` | `packages/credential` |
| 前端 live adapter 重复 | `liveRunAdapters.ts`、`liveTaskAdapters.ts` | 统一 ViewModel 层 |
| 文件下载 URL 手拼 | `dashboard/lib/api.ts`、`mobile/lib/api.ts` | `packages/api-sdk` 文件能力 |

## 11. 前端到运行时完整链矩阵

| 顺序 | 触发方 | 下游 | 结果 |
|---|---|---|---|
| 1 | 用户点击服务启动 | `build*RunInput()` | 形成启动参数 |
| 2 | 前端 mutation | `createRun()` | 返回 runId |
| 3 | 页面导航到任务详情 | `getRun()` + `runStream` | 建立对话上下文 |
| 4 | API 业务层 | worker / bridge | 后台运行推进 |
| 5 | bridge 回流事件 | API -> Query Cache | 页面消息与状态更新 |
| 6 | 用户继续对话 | realtime send 或 HTTP mutation | 实例继续推进 |

## 13. 当前阻塞项总表

| 阻塞项 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| API 持久化、事件、文件逻辑仍集中在一个域 | `runsService` 负担过重 | 后端可维护性不足 | P0 |
| Worker 与 bridge 的正式边界未封装成独立 runtime 包 | 运行链跨仓耦合高 | 扩展与部署困难 | P0 |
| 前端静态数据层与 live adapter 并存 | 工坊/Creator/任务链口径分裂 | 联调成本高 | P1 |
| store、Query、URL 三套状态源尚未统一治理 | 页面刷新与跨页行为复杂 | 交互一致性不足 | P1 |
