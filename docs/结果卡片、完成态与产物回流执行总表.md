## 2. 当前事实矩阵

| 主题 | 当前证据 | 当前结论 | 当前缺口 |
|---|---|---|---|
| Mobile 完成态 | `liveTaskAdapters.ts` 在 `SUCCEEDED` 生成 `result` 模块，`eta` 变为“已完成” | H5 有完成态语义 | 结果卡片仍由 adapter 推导 |
| Dashboard 结果消费 | 实例页已有文件页、状态标签和结果提示文案 | Dashboard 可消费结果文件 | 无正式结果卡片层 |
| API 产物回流 | `syncArtifacts()` upsert `artifacts` 并广播 `artifact.ready` | 后端已有产物事件主链 | 缺 bundle 级摘要与结果摘要对象 |
| seed artifact | `receipts/output/archive` 目录会被播种为 pending artifact | 已有最小 artifacts 容器 | 语义偏占位，不等于真实交付物 |
| 结果消息回写 | 当前主要依赖文件存在性 + 状态推导 | 对话内结果可弱表达 | 缺显式完成回执卡片 |

## 4. 完成态状态机总表

| 状态 | 含义 | 当前来源 | 正式行为 |
|---|---|---|---|
| `running` | 实例仍在执行 | `run.status` 非终态 | 对话可继续，结果卡仅显示中间产物 |
| `succeeded_pending_results` | run 已成功但结果摘要未完成收敛 | 当前缺失 | 等待 `artifact.ready/result.summary.ready` |
| `result_ready` | 关键结果已可消费 | 当前由 `SUCCEEDED + visibleFiles` 弱推导 | 展示正式结果卡片 |
| `archived` | 结果已转存或归档 | 当前缺失 | 结果卡显示归档位置 |
| `rerunnable` | 允许再次运行 | 当前可从上下文字段弱推导 | 显示再次运行动作 |
| `failed` | 实例失败 | 已有 | 引导读取错误和中间结果 |

## 5. 结果卡片状态矩阵

| 状态 | 标题 | 主动作 | 次动作 | 必要字段 |
|---|---|---|---|---|
| `pending` | 结果整理中 | 查看当前文件 | 继续追问 | `runId/progressHint` |
| `ready` | 结果已生成 | 查看结果 | 下载全部 | `bundleId/summary/files` |
| `rerunnable` | 结果可复用 | 再次运行 | 派生任务 | `rerunTemplate/actions` |
| `archived` | 结果已归档 | 打开归档位置 | 转存到我的 | `archiveRef` |
| `failed` | 结果整理失败 | 查看错误 | 继续恢复 | `errorCode/errorHint` |

## 6. 产物回流执行链总表

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | Codex / runtime | 生成文件 | 写入 `target/output/archive/receipts` | 本地产物 |
| 2 | Bridge | 监听文件或显式发布产物 | 发送 `file.changed/files.synced/artifact.ready` | bridge events |
| 3 | API | `ingestBridgeEvents()` / `syncArtifacts()` | 回写 `files[]/artifacts[]` | 新快照 |
| 4 | Event bus | 广播状态与产物事件 | 推送到 WS/SSE | 前端实时更新 |
| 5 | 前端 adapter | 消费快照与事件 | 生成结果卡片、文件列表、列表标签 | UI 更新 |
| 6 | 资产/通知层 | 根据完成态投影 | 更新“我的资产”、通知中心、统计卡 | 跨页面收敛 |

## 10. Query 与缓存失效矩阵

| 触发事件 | 当前行为 | 正式缓存动作 |
|---|---|---|
| `artifact.ready` | 主要刷新快照 | 失效 `runs/:id/results`、`me/assets` |
| `files.synced` | 刷新文件树 | 若命中输出目录则尝试刷新结果摘要 |
| `run.status.changed -> SUCCEEDED` | 任务状态变为完成 | 进入 `succeeded_pending_results`，等待结果就绪 |
| `result.bundle.ready` | 当前缺失 | 列表、详情、通知、资产同时更新 |
| `save-to-assets` 成功 | 当前缺失 | 刷新 `me/assets`、结果卡片归档状态 |

## 14. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 结果卡片对象未正式化 | 双端各自推断完成态 | 展示不一致 | P0 |
| Dashboard 无结果卡片层 | Web 端结果消费效率低 | 重度用户体验不足 | P0 |
| 完成态与结果就绪未分层 | `SUCCEEDED` 与“结果可消费”混在一起 | 容易误导用户 | P0 |
| 产物回流未联动资产与通知 | 完成后只停留在当前实例页 | 资产沉淀不足 | P1 |
| `artifact` 语义偏弱 | 目录占位和真实交付物混在一起 | 后续 bundle 化困难 | P1 |
