## 1. 文档信息

| 字段 | 内容 |
|---|---|

| 统计日期 | 2026-07-08 |

## 2. 当前合同事实矩阵

| 对象 | 当前字段 | 当前作用 | 当前缺口 |
|---|---|---|---|
| `runConversationAttachment` | `path`、`label` | 消息级附件引用 | 无上传对象主键 |
| `sendRunMessageInput.attachments[]` | 附件数组 | 允许消息带附件引用 | 前后端未形成上传闭环 |
| 文件读接口 | `/files/tree`、`/files/stat`、`/files/read`、`/files/download` | 可读 targetPath 现有文件 | 不负责上传 |
| API SDK | `listRunFiles/readRunFile/...` | 已有读链 | 无附件上传 SDK |

## 3. 正式附件上传链路矩阵

| 步骤 | 执行方 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 前端 | 本地文件 | 读取文件名、大小、MIME、用途 | 上传前元数据 |
| 2 | API | `filename`、`mime_type`、`size_bytes`、`material_kind` | 校验 run 权限并生成 `upload_ticket` | 预签名上传票据 |
| 3 | 前端 | `upload_ticket` + 文件内容 | 直传对象存储 | 已上传对象 |
| 4 | API | `upload_id`、`storage_key`、`checksum`、`label` | 生成 `input_material` 与 `message_attachment` | `attachment_ref` |
| 5 | 前端 | 文本 + `attachment_ref[]` | 调用 `sendRunMessage()` | 对话消息入库 |
| 6 | Worker/Bridge | 新附件引用 | 同步/挂载到 `inputs/` | Codex 可消费材料 |

## 4. `upload_ticket` 字段矩阵

| 字段 | 类型 | 用途 |
|---|---|---|
| `upload_id` | string | 本次上传任务主键 |
| `method` | string | 上传方法 |
| `url` | string | 预签名 URL 或直传 URL |
| `headers` | object | 上传必须携带的头 |
| `expires_at` | datetime | 票据过期时间 |
| `max_size_bytes` | number | 最大允许大小 |
| `allowed_mime_types` | string[] | 允许的 MIME |
| `storage_key` | string | 预分配对象存储 key |

## 6. `input_material` 字段矩阵

| 字段 | 类型 | 用途 |
|---|---|---|
| `input_material_id` | string | 输入物料主键 |
| `run_id` | string | 所属 run |
| `workspace_id` | string | 所属工作区 |
| `storage_key` | string | 对象存储 key |
| `mount_target` | string | 容器内挂载目标 |
| `material_kind` | `document / image / archive / browser-state / spreadsheet / other` | 物料类型 |
| `display_name` | string | 展示名称 |
| `checksum` | string | 校验摘要 |

| `created_at` | datetime | 创建时间 |

## 7. 容器挂载执行矩阵

| 物料类型 | 建议容器内路径 | 作用 |
|---|---|---|
| 文档/PDF/表格 | `/workspace/inputs/docs/<filename>` | 供 Codex 读取业务材料 |
| 图片/参考图 | `/workspace/inputs/images/<filename>` | 供视觉类工作流读取 |
| 压缩包/素材集 | `/workspace/inputs/packages/<filename>` | 供解压、归档、批处理 |
| browser state / cookie | `/workspace/secrets/browser/<filename>` | 敏感材料，不进入公开 `inputs` |
| 工作区共享材料 | `/workspace/inputs/shared/<filename>` | 供多 run 复用 |

## 10. 权限执行矩阵

| 动作 | 最低权限 | 关键校验 |
|---|---|---|
| 上传消息附件 | `operator` | 当前工作区可访问该 run，文件大小与类型符合策略 |
| 查看附件元数据 | `member` | 当前工作区拥有该 run |
| 下载附件 | `member` | 附件可见性允许且属于该 run/workspace |
| 删除附件 | 上传人、run owner 或 admin | 避免删除关键在用材料 |
| 引用工作区共享材料 | `operator` + 共享材料读取权 | 共享材料自身的授权单独校验 |

## 11. 与槽位收集链路联动矩阵

| 场景 | 触发对象 | 联动动作 |
|---|---|---|
| 用户补交报税材料 | `input_material` | 回填到 `file` 槽位 |
| 用户补交参考图 | `input_material` | 回填到 `image` 槽位 |
| 用户补交浏览器状态 | `credential` 或 `browser-state` 物料 | 进入敏感材料链，不走普通预览 |
| 用户删除附件 | `message_attachment` | 槽位状态可能回退为 `missing` |

## 12. 当前缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无附件上传接口 | 仅有 schema | 对话补材料无法正式化 | P0 |
| 无附件正式对象 | path/label 过于轻量 | 无法追踪来源、权限、版本 | P0 |
| 无容器挂载同步逻辑 | `inputs/` 目录虽已规划，但未联动附件 | Codex 无法稳定读取新材料 | P0 |
| SDK 无上传能力 | 仅覆盖读链 | 双端无法接入正式附件流程 | P1 |

## 15. 附件收口顺序表

| 阶段 | 动作 | 收口结果 |
|---|---|---|
| Phase 1 | 落地 upload ticket / complete upload API | 前端可正式上传材料 |
| Phase 2 | 落地 attachment/material 正式对象 | 附件来源、权限、版本可追踪 |
| Phase 3 | 把附件同步到 `inputs/` 或 secret 挂载链 | Codex 可稳定消费新材料 |
| Phase 4 | 补 SDK、预览、下载授权 | 双端附件体验闭环 |
