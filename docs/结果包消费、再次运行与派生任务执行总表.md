## 10. 再次运行执行链矩阵

| 步骤 | 执行方 | 当前可复用事实 | 正式要求 |
|---|---|---|---|
| 1 | 前端 | 双端已有 `build*RunInput()` 模板构造器 | 从结果页直接拿 `rerun_template` |
| 2 | API | 已有 `POST /v1/runs` 创建入口 | 新增 `POST /v1/results/:bundleId/rerun` |
| 3 | API | `CreateRunInput` 已含 `taskVersionId/sessionVersionId/bindings` | 从 `source_run_id` 恢复默认参数 |
| 4 | Worker | 已能为新 run 生成 target/output/runtime 目录 | 需记录 `rerun_of_run_id` lineage |
| 5 | 前端 | 进入新实例对话页 | 结果页与旧实例页都可追踪 lineage |

## 11. 派生任务执行链矩阵

| 步骤 | 执行方 | 当前状态 | 正式要求 |
|---|---|---|---|
| 1 | 用户 | 当前只能在对话里手动描述“继续派生” | 结果卡片或结果页提供结构化派生动作 |
| 2 | 前端 | 可把“继续派生”写成下一条草稿 | 形成 `derived_run_request` 并允许补充派生参数 |
| 3 | API | 当前无派生专用接口 | 新增 `POST /v1/results/:bundleId/derive` |
| 4 | API/Worker | 当前不会记录来源 bundle | 新 run 需关联 `source_run_id/source_bundle_id/source_asset_item_ids` |
| 5 | 审计 | 当前无 lineage | 派生链需可追溯到原始结果与输入差异 |

| 事件/动作 | 当前行为 | 正式缓存动作 |

## 14. 权限与审计矩阵

| 动作 | 最低权限要求 | 审计要求 |

## 15. 当前结构性缺口总表

| 缺口 | 当前表现 | 影响 | 优先级 |
|---|---|---|---|
| 无独立结果域 | 结果消费仍围绕文件列表与消息文案 | 无法形成 bundle 级治理与下载体验 | P0 |
| Dashboard 缺结果卡片 | Web 端只有文本消息和文件页 | 重度用户结果消费效率不足 | P0 |
| 再次运行无正式入口 | 只能从服务页重新发起 | 无法保留结果上下文与 lineage | P0 |
| 派生任务无结构化对象 | 只能靠自然语言续聊 | 难以形成标准化自动化链路 | P0 |
| seed artifact 语义偏弱 | 当前为目录占位而非真实交付物 | artifact 权威性不足 | P1 |
| 我的资产无 bundle 概念 | 资产仅按文件扁平展示 | 结果沉淀与分享能力不足 | P1 |
